# GitHub: исходники и размещение лендинга

Состояние: вариант A опубликован 2026-10-30 в отдельном репозитории. Сайт: https://avyakunichkin-code.github.io/tvoy-plan-landing/. Ниже сохранён способ размещения; фактические результаты — [DEPLOYMENT.md](./DEPLOYMENT.md).

## Можно ли разместить

Да, технически текущая информационная страница — статические HTML/CSS/JS, поддерживаемые [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Можно также хранить исходники на GitHub, а размещать сайт через Sites или другой хостинг.

Рекомендация — отдельный репозиторий, например `tvoy-plan-landing`: GitHub даёт один Pages-сайт на репозиторий. В текущем проекте уже есть настройки/команды Pages для игры, их нельзя заменять публикацией лендинга.

Это подходит для представления прототипа без анкеты и транзакций. [Правила Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) запрещают использовать сервис для коммерческих транзакций и коммерческого SaaS. Подключение реального приложения, входа и финансовых данных — отдельная задача и не входит в этот лендинг. Возможность конкретной коммерческой публикации нельзя выводить только из технической совместимости HTML.

## Минимальный путь после утверждения дизайна

1. Зафиксировать выбранный A/B и подготовить чистый выпуск без lab-панели. Добавить canonical и изображение для социальных ссылок после выбора окончательного адреса.
2. Создать отдельный репозиторий. Для GitHub Free Pages доступен из публичного репозитория; приватные репозитории зависят от тарифа. Приватность репозитория сама по себе не делает Pages-сайт приватным.
3. В корень нового репозитория загрузить **только** `index.html`, `styles.css`, `site.js`, `favicon.svg` из `dist/`, добавить пустой `.nojekyll`. Не переносить монорепозиторий, `.openai/hosting.json`, `.git`, окружения, backend, реальные данные или служебную историю.
4. В `Settings → Pages` выбрать `Deploy from a branch → main → /(root)` и сохранить. Это поддерживаемый [способ публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) без сборки.
5. Проверить выданный GitHub адрес: оба относительных ресурса CSS/JS, favicon, кириллицу, кнопки, якоря и мобильный экран. Можно подключить свой домен и HTTPS.

Все локальные пути ресурсов относительные (`./`), поэтому подходят и для project Pages под `/имя-репозитория/`. Папка `dist` используется как источник для Sites, а её содержимое — как корень нового GitHub Pages репозитория.
