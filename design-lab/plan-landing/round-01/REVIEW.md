| CSS order варианта B расходился с порядком чтения | Перемещение блока в DOM; клавиатурный и визуальный порядок совпадают |
| На телефоне длинный заголовок расширял grid | `minmax(0,1fr)`, `min-width:0` и адаптивный размер кириллического заголовка |
| Вопросы не работали без JS | Якорные ссылки; базовые текстовые разделы и FAQ доступны без JS |
| Недостаточная видимость focus на тёмном фоне | Отдельный светлый outline, skip-link; сценарии имеют aria-pressed, live region atomic |
| CSS import задерживал обнаружение шрифтов | Stylesheet в head с preconnect; сохранён font-display=swap |

## Сопоставление с решениями, доступными в 2026 году

Это сравнительная экспертная оценка, а не рейтинг «лучших сайтов 2026» и не исследование конверсии.

- [Monarch](https://www.monarch.com/): ясная ценность для финансов семьи, показ предметных функций и результата. Применено к собственной области Plan, без переноса банковских интеграций и совместного доступа.
- [Linear](https://linear.app/): предметная демонстрация продукта рядом с ценностным предложением. Применена демонстрация структуры отчёта вместо абстрактных обещаний.
- [NN/g — Homepage Design: 5 Fundamental Principles](https://www.nngroup.com/articles/homepage-design-principles/): назначение сайта должно быть понятно сразу, следующий шаг очевиден. Поэтому hero объясняет чекап, главный CTA ведёт к отчёту. Руководство опубликовано в 2024 году, актуальность подхода оценивается на дату проверки, не выдаётся за новый тренд 2026.
- [WCAG 2.2 — Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): минимум 24 CSS px с оговорёнными исключениями. Управляющим кнопкам сценариев и FAQ задано минимум 44 px.
- [Core Web Vitals](https://web.dev/articles/defining-core-web-vitals-thresholds): скорость показа, отзывчивость и стабильность. Статика без фреймворка, четыре локальных файла ~36 КБ без шрифтов. Это размер исходных ресурсов, не результат Lighthouse и не доказательство CWV.
