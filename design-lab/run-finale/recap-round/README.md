# recap-round — разбор партии в финале

Статус: **утверждён вариант Б (09.11.2026)**, перенесён в prod, см. [`../APPROVED.md`](../APPROVED.md). Данные — [SPEC_run-finale-recap](../../../docs/game/specs/features/SPEC_run-finale-recap.md). Канон текущего финала — [`../bg2-page-round/`](../bg2-page-round/).

Задача: сейчас победа показывает три числа, а поражение — факт и советы. Игрок не видит, какие решения сформировали партию.

| Вариант | Идея | Цена |
|---|---|---|
| А · График с отметками | Форма партии и три пронумерованных решения | Самый плотный экран |
| Б · Лента решений | Партия как короткая история | Не видно динамику денег |
| В · Один поворот | Малый график и одна главная трата, остальное по кнопке | Лишнее нажатие до полной истории |

На поражении блок тот же; победные числа заменяются фактом и советами. Демо-партия одинакова во всех вариантах, суммы условные.

## Что нужно для внедрения

- **График:** `period_economy_closings` хранит счёт, подушку и долг за каждый ход. Вложений там нет, поэтому линия — счёт + подушка − долг, и подпись это говорит.
- **Решения:** `EventInstance.selected_choice_id` хранит выбор. Сумму эффекта и правило отбора «главных» решений нужно определить в spec.
- **Формулировки:** только факты, без «из-за этого ты выиграл»: причинность по этим данным не доказать.
- Новые поля в `run_finale` — additive API; партии до внедрения могут не иметь полной истории, нужен честный fallback на текущий финал.
- «Поделиться итогом»: сейчас такой функции нет. Вид карточки — отдельный вопрос после выбора варианта.

## Запуск

```bash
cd design-lab && npx serve .
```

Хаб `/` → «Run finale — разбор партии». После правки стилей: `./sync-lab.sh`, затем в `frontend-react` — `npm run design-lab:check-rounds`.
