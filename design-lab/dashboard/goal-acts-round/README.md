# goal-acts-round — цель в два акта (review)

Блок «Цель» с подписью «Акт N из 2» и финал акта 1 по [`SPEC_victory-acts`](../../../docs/specs/features/SPEC_victory-acts.md) (DRAFT; спека приходит с PR #16). План — [`PLAN_victory-acts`](../../../docs/plans/PLAN_victory-acts.md), задача MQ-ACT-10.

**Статус:** review, 2026-11-02. ★ нет. В prod (`MqxGoalDash`, `MqxRunFinale`) не переносить, пока PO не скажет «утверждаем».

## Варианты

| Вариант | Что | Цена |
|---------|-----|------|
| **A** (рекомендую) | «Акт K из 2 · шаг N из M» в подписи; точки — шаги текущего акта | Новых элементов нет, высота блока та же |
| B | Плашка «Акт K из 2» над словом «Цель» | Блок выше примерно на 18 px, ещё один акцент |
| C | Как A, плюс золотая медаль «1» пройденного акта перед точками акта 2 | Новый элемент, нужен текст для экранного диктора |

Общее для всех вариантов:

- раскрытая цель акта 2 — строка «Акт 1 пройден на ходу N», одна реплика Монетки при первом показе, шкала «сейчас X% · нужно Y%» вместо точек (у акта 2 одна цель с долей);
- финал акта 1 — финал ★ BG-2 с надписью «Акт 1 из 2», карточкой «Дальше — акт 2» и кнопкой «К сохранениям» вместо «Новая игра»;
- финал акта 2 — нынешний победный.

Цифры — партия «Студент» по эталону `chain_runner` после калибровки A (акт 1 на ходу 15). Порог 15% — черновик из Open question 1 плана.

Слой «Чернильный край» (`styles/mqx/ink.css`) здесь не применён: база — канон ★ BG-1/BG-2. Если ink утвердят, при переносе в prod подпись акта берёт стили `.mqx-bg-goal__step`, а медаль варианта C нужно отдельно проверить в ink.

Хаб: `cd design-lab && npx serve .` → Dashboard → «Цель в два акта».

cd design-lab/dashboard/goal-acts-round && ./sync-lab.sh && npx serve .
