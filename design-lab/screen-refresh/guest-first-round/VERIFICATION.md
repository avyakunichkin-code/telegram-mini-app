# Гостевой старт А · проверка внедрения

07.11.2026. Человеческое утверждение: [APPROVED.md](APPROVED.md). Без коммита и внешней публикации.

## Реализовано

- Публичный `#/` → утверждённый А, компактный белый заголовок, G1 с подписью, новый текст.
- Настоящий серверный гость, HttpOnly-cookie на 180 дней; пароль/почта не требуются до игры. Access JWT восстанавливается через действующую сессию.
- `/api/game/guest-start` продолжает партию при повторе. Обычный `/api/game/start` позволяет новую игру, в том числе после поражения. Подготовка партии атомарна; PostgreSQL блокирует строку владельца при конкурентном старте.
- Web Locks сериализует первое создание между вкладками в поддерживаемых браузерах. Для браузера без Web Locks эта межвкладочная гарантия отсутствует.
- Версия 2 закрепляется на новой гостевой партии, остаётся после регистрации. Краткие необязательные подсказки: зарплата → событие → закрытие. Подушка доступна без обязательного учебного взноса. Старые партии продолжают O3.
- События версии 2 — с первого хода. На первых двух ходах открываются вручную, чтобы не прерывать итог/привязку. Старое intro не дублируется.
- После первого реального итога — добровольное предложение регистрации; отказ не мешает игре, ссылка остаётся в меню. Claim меняет того же User, сохраняет profile_id/владение и отзывает старую гостевую сессию/JWT. Вход в другой аккаунт не сливает сохранения.

## Практические ограничения

Проверены Chrome mobile/desktop и локальная PostgreSQL; отдельный многопроцессный concurrency-тест PostgreSQL не запускался. На внешнем API требуются credentialed CORS и cookie, предпочтителен same-origin proxy. Ограничение создания гостей — per-process, не распределённое. Автоматическое удаление гостевых данных и слияние с существующими аккаунтами не включены.
