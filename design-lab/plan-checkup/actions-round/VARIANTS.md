# P3-02 · действия внутри шага

Статус: **B утверждён владельцем 2026-11-05** («Супер, утверждаем» после доработки). База — утверждённый билет S1. A — сравнительный вариант.

Уточнение владельца 2026-11-05: предпочтён компактный B, доработать перед утверждением. В B единственный счётчик «Выполнено N из M» перенесён в summary вместо «Действия шага». Шкала включена в область раскрытия; справа круглая стрелка. Список изолирован от горизонтального `.actions` приложения: одна строка на действие, одинаковая колонка чекбоксов, кликабельная строка. Чекбоксы 26 px со скруглением и контрастной галочкой, состояния checked/focus/disabled и системный fallback для forced-colors. Это доработка lab, не разрешение переноса в приложение.

- **A — открытый список (рекомендация):** 1–3 действия видны сразу, прогресс рядом. Один дополнительный клик не нужен.
- **B — раскрытие:** тот же билет, список в details; компактнее при нескольких шагах, действия менее заметны.

Одинаковые синтетические данные: резерв 25 000 ₽, пополнение 15 000 ₽. Три действия: выбрать отдельный счёт, самостоятельно пополнить, проверить зачисление. Это дизайн-пример, не новый финансовый порог.

Состояния: начало, частично, saving/disabled, ошибка с повтором, done автоматически, done вручную, dismissed, loading, legacy/empty, offline. Можно выбрать 1/2/3 действия. Повторное открытие сохраняет подтверждённые отметки в памяти страницы, без localStorage и реальных данных. Ошибка не подтверждает отметку. Последняя отметка завершает шаг; снятие отметки возвращает его в работу. Ручное завершение не проставляет невыполненные действия. Возврат в работу сохраняет отметки, но снимает последнюю, если выполнены все. Эти переходы предложены для утверждения вместе с вариантом.

После выбора: actions рядом с шаблонами правил 1–7/11; стабильный key, текст и done; PATCH действия с household isolation; серверный прогресс и старые отчёты; idempotent retries и тесты. `step_action_done` содержит только rule_key и key действия. P3-09 отдельно уточнит остальные события. Старые отчёты без действий продолжают поддерживать ручную отметку без пересчёта.

Очередь владельца 2026-11-05: P3-02 → P3-09 → P3-08 → P3-12. История сравнивает сохранённые завершённые чекапы без пересчёта; офлайн включает дату данных и очистку при выходе/удалении.
