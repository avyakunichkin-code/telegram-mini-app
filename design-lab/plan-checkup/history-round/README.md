# P3-08 · история и сравнение

**Текущий статус: вариант 2 (B) «Журнал с полями» утверждён владельцем:**
«Утверждаем 2 Журнал с полями». Зафиксировано 2026-11-06 при внедрении в Plan.
Канон и адаптация — [APPROVED](../APPROVED.md), реализация — History.jsx/history.css
в apps/plan-web. Ниже сохранена история итераций; статусы review относятся к ним.

Текущий раунд — **три гибрида** по последнему поручению владельца: удобная
таблица «Показатель / Было / Стало / Изменение» во всех вариантах, разная степень
выразительности вокруг неё. 1 (A) — чистый журнал с архивом слева; 2 (B) —
закладки, поля и небольшая заметка; 3 (C) — разворот и цельная таблица на отдельном
листе. По умолчанию открыт 2. Источники — `hybrid.js` / `hybrid.css`.
Данные, 5 метрик, 4 области, выбор дат и состояния совпадают. На телефоне
каждая строка сохраняет пару «Было / Стало», изменение показано под ней.
Утверждён гибрид 2; 1 и 3 остаются вариантами для сравнения.

Вход — [хаб](../../index.html),
раздел «ТВОЙ ПЛАН», пункт «P3-08: история и сравнение A/B».

Владелец выбрал направление B с поручением сделать креативнее и удобнее.
**B3 · Журнал-разворот** заменяет B v2 после замечания владельца, что доработка
была недостаточно креативной. Финального утверждения B3 ещё нет.
Это новый визуальный принцип: закладки месяцев, два заголовка страниц «Тогда /
Сейчас», сгиб и листы, заметка между страницами, парные строки чисел вместо
карточек. Месячная закладка открывает пару с предыдущей записью; для первой
записи — пару с ближайшей следующей. «Выбрать даты» позволяет задать любую
хронологически допустимую пару. Полный архив раскрывается ниже разворота.
На телефоне сохраняются пары значений в одной строке, дельта переносится под
ними; декоративный сгиб убирается, быстрые пары и полные отчёты доступны.
Источник нового оформления — `book.css`, композиции — `book.js`.

Предыдущая итерация **B v2**:
Главный результат вынесен в заметку, есть быстрые пары «С предыдущим» / «С первым
чекапом», записи помечаются «Было» и «Стало», метрики собраны в компактные карточки.
На телефоне сравнение идёт первым, журнал раскрывается ниже; черновик перенесён
в конец. Состав метрик и финансовые правила не менялись.

- **A · Архив карточек** — завершённые чекапы отдельными карточками над сравнением.
  Удобно рассмотреть вопрос и состояние каждого отчёта.
- **B · Журнал (рекомендация)** — компактная история слева, сравнение справа;
  на телефоне история перед сравнением. Меньше прокрутки на широком экране.

Одинаковые синтетические отчёты за сентябрь, октябрь и ноябрь 2026. Кнопки
открывают сохранённое превью и выбирают пару для сравнения. «Было» всегда раньше
«Стало», один и тот же отчёт выбрать дважды нельзя. Черновик выделен отдельно
и недоступен для сравнения. Счётчик, суммы и дельты не являются новыми правилами.

Состояния: ready, loading, empty, error/retry, один завершённый отчёт (сравнение
недоступно), отсутствующая старая метрика (не ноль), разные версии расчёта
(пояснение вместо вывода о причинах цвета), offline/disabled. Новый чекап и
продолжение черновика — обозначенные переходы, а не полноценный мастер в lab.

Сравниваются четыре области и пять метрик:

| Подпись | Сохранённое поле отчёта |
|---|---|
| Свободный остаток в месяц | free_cashflow |
| Подушка в месяцах расходов | metrics_base.safety_fund_months |
| Платежи от дохода | metrics_base.dti_percent (разница в п. п.) |
| Общий долг | metrics_base.total_debt |
| Капитал семьи | net_worth |

Дата завершения и месяц данных показаны отдельно. Дельты — арифметическая
разница двух снимков, без нового запуска движка. Цвет не обозначает оценку
каждой денежной дельты; сохранённый риск областей показывается словами и формой.
Разные rules_version не запрещают читать числа, но предупреждают, что изменение
цвета может объясняться версией правил. Будущий API должен проверять household_id
обоих завершённых чекапов и читать reports.payload_json, без build_report.
Нет сохранённого отчёта — явная ошибка, не скрытая регенерация.

Не входит: прогресс отдельных целей P3-07, перенос действий между чекапами P3-03,
PWA-кэш P3-12, новый аналитический event. Публичный API и приложение до выбора
варианта не меняются. Утверждение агента не заменяет выбор владельца.

Стили базы генерируются `node design-lab/plan-checkup/history-round/sync-lab.mjs`
из корня. `lab-base.css` вручную не редактировать. Разметка использует локальные
CSS и JS; шрифты из внешних сервисов не подключаются.
