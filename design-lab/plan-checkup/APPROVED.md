## ★ P3-07 · 2 «Маршрут цели» + поздравление · 2026-11-06

Владелец выбрал «Маршрут цели», попросил сделать достижение поздравлением/наградой,
посмотрел обновлённый lab и ответил **«Да, отлично»**, затем **«Внедряй»**.
Источник: goals-round, вариант B; A/C — сравнительные варианты.
Композиция: три точки «было / сейчас / цель», прогресс и изменение суммы слева,
наблюдаемый темп, нужный взнос и срок справа. На телефоне блоки идут последовательно.
Остальные цели раскрываются по запросу. При достижении суммы — медаль, «Получилось.
Вы это сделали!», сумма и завершённый маршрут вместо прогноза. Награда статична,
относится к накоплению суммы по данным чекапа, не к подтверждённой покупке.

Реализация в отдельном Plan-компоненте GoalRoutes.jsx/goal-routes.css; игровой MQX
не изменён. Данные берутся из API. Старые сохранённые отчёты без progress сохраняют
свою таблицу. Сравнение по стабильному ID, неизвестные прошлые данные не заменяются
нулём. Темп за неполный интервал без смены месяца не рассчитывается. Без срока —
подсказка; при нулевом/отрицательном темпе — нет даты прогноза. Snapshot хранит
контекст сравнения и доступен офлайн; свободный остаток не объявляется взносом.

## ★ P3-03 · 3 «Мост между шагами» · 2026-11-06

Владелец явно выбрал: **«Давай выберем 3 Мост между шагами»**.
Источник — continuity-round, вариант C. A/B остаются сравнительными.
При повторном чекапе прошлый шаг слева, текущий справа; на телефоне последовательно.
Статус/отметки прошлого шага и изменение метрики показаны отдельно, без утверждения
причинной связи. Остальные прошлые шаги раскрываются ниже. Первый чекап и старые
отчёты без контекста сохраняют прежний layout.

Реализация: PreviousStepBridge.jsx/previous-step.css в apps/plan-web. Используются
существующие Plan Button/StepActions. Для полного «моста» ответ A2 перед ним занимает
полную ширину; текущий билет S1 перенесён в правую половину моста. В примере lab
показан взнос 12 000 ₽, но в приложении заголовок и приоритет нового шага всегда
определяются API, без изменения финансовых правил ради иллюстрации.
Открытие прошлого отчёта имеет возврат «К новому разбору». Офлайн — только чтение.
Длинные значения метрики занимают полную ширину, денежные суммы не разрываются.
Контекст зафиксирован при завершении нового отчёта, поздняя отметка старого шага
не переписывает уже завершённый снимок.

## ★ P3-08 · вариант 2 «Журнал с полями»

Явное утверждение владельца в чате: **«Утверждаем 2 Журнал с полями»**.
Зафиксировано при внедрении 2026-11-06. Источник — history-round/hybrid.js,
hybrid.css, вариант B. Варианты 1 и 3 остаются сравнительными, не каноном.

Композиция: заголовок и новый чекап → год/закладки последних записей → архив
слева и сравнение справа → черновик отдельно. В сравнении: быстрые пары,
селекторы «Было/Стало», небольшая заметка, таблица из 5 метрик, 4 области,
месяцы данных и версии расчёта. На телефоне архив раскрывается ниже сравнения;
строка метрики показывает пару значений и изменение под ней, без горизонтального
скролла. При одном итоговом отчёте доступно его открытие, сравнение отключено.

Реализация: отдельный `apps/plan-web/src/screens/History.jsx`, `history.css`,
`history-format.js`. Кнопки используют Plan Button → общий ButtonBase, без
импорта MQX игры. Даты, вопросы, области и суммы приходят из сохранённых отчётов;
три иллюстративных месяца из lab не становятся данными приложения. Номер записи
в селекторе различает чекапы одной даты. Отсутствующая старая метрика — «Нет
данных», разные версии — предупреждение. Исходные отчёты не пересчитываются.


Состояние P3-12 (поведение существующего отчёта, 2026-11-05): при чтении
локального итогового снимка в существующей строке даты показаны «Офлайн · только
чтение» и время сохранения копии. Состав и layout отчёта не меняются, запись
и новый чекап disabled. Это реализация поручения об офлайн-чтении, а не новое
утверждение layout. Для истории P3-08 утверждён вариант 2 «Журнал с полями», см. выше.

Дизайн-система — «Бенто» (токены — `apps/plan-web/src/styles.css`, копия для lab — `styles.css` этой папки). Не MQX игры.

## ★ Отчёт: первый экран — C2 (утверждено PO 2026-11-02)

Раунд: [`bento-round`](bento-round/README.md), вариант **C2 · C + график прогноза**. Prod: `apps/plan-web/src/screens/Report.jsx`.

Порядок блоков сверху вниз:

1. Строка-шапка: «Черновой / Итоговый разбор на {месяц}» + пилюля точности.
2. **Светофор 2×2** — четыре цветные плитки областей (Бюджет, Долги, Подушка и цели, Инвестиции и защита): одна главная цифра и подпись. На десктопе — 4 в ряд.
3. **«Деньги на счетах»** — график на 12 месяцев, две линии: «как сейчас» (сплошная) и «если хуже» (пунктир, нижние доходы и верхние расходы); ноль подписан, зона ниже нуля подсвечена; легенда с конечными суммами.
4. **Ответ на вопрос со входа** — графитовая плитка: вопрос, вердикт, главная цифра, текст; внутри — «С чего начать» (3 шага, следующий выделен жёлтым, отметки «Сделано / Не подходит»).
5. «Остаётся в месяц» и точность ввода.
6. Подробно по областям, стресс-тест, кредиты, цели, дисклеймер — как в прототипе.

Инварианты: красный — только для фактов (минус, просрочка), не для оценки людей; суммы без переноса внутри числа; на 375 px без горизонтальной прокрутки (e2e CS-11).

Отступление от spec: в `SPEC_plan-v1` (UI/UX) ответ стоял выше светофора — spec поправлен под C2 тем же решением PO.

## Реализация композиции в приложении · 2026-11-04

Утверждённая композиция перенесена в `apps/plan-web/src/screens/Report.jsx`:
прогноз F2 и подушка M1 — `ReportBlocks.jsx`, оформление — `report-blocks.css`.
A2 показывает ответ API и его метрику для выбранного вопроса, без фиксированной
суммы из примера. S1 показывает первый шаг API, его объяснение и доступные
отметки; остальные шаги вынесены ниже подробностей. Первый шаг сохраняет своё
место после done/dismissed; это не автоматическое продвижение следующего шага.

Две дорожки F2 заменяют основной график C2; графики стресс-тестов сохранены.
Начальный запас — введённые ликвидные счета и подушка; конечные значения — API.
Цель M1 зависит от расходов и target_months API; при нулевых расходах показан
запрос уточнения вместо фиктивной цели. Для первого пополнения/месячного взноса
S1 результат использует step.numbers; для других действий денежный результат
не выдумывается. Фактический цвет риска области подушки сохраняется.

Порядок и темы проверяются в E2E, включая ширины 375/701/792/1050/1440 и contrast
пояснения прогноза. Реализация не означает внешнюю публикацию или допуск к
реальным данным. Подробности — docs/plan/audits/2026-11-04-report-integration.md.
