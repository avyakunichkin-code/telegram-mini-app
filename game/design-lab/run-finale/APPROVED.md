**Базовый parity BG-2:** [`bg2-page-round/`](bg2-page-round) — снимок до DC-08, без блока решений, три состояния: победа, поражение по `cash_negative_streak`, поражение по `needs_depletion`. **История:** V1 «Газета» ★ 2026-06-01 ([`index.html`](index.html), [`VARIANTS.md`](VARIANTS.md)) — заменён BG-2, не канон.

## Порядок блоков — победа

1. **Золотая клетка финиша** с персонажем и кубком (`assets/run-finale-cup/*-cup-dash`), объём снизу — золотой край.
2. **«Цель пройдена!»**.
3. Короткая фраза по сценарию — `scenario_title` из API.
4. **Три показателя**: ходов (`period_index`) · на счёте (`cash_balance`, золотом) · ходов подушки (`cushion_turns`). Нет данных — «—».
5. **«Играть дальше»** — главная (фиолетовая), партия продолжается (SPEC_victory-v2 F1, `POST /api/game/run-finale/dismiss`).
6. **«Новая игра»** · другая жизнь — вторая кнопка, сразу к выбору жизни (ADR-013).
7. Необязательный отзыв: поле + «Отправить отзыв» (`POST /api/game/run-feedback`).

## Порядок блоков — поражение

1. **Нейтральная клетка** с портретом персонажа (без золота).
2. **«Партия окончена»** + «Она уйдёт в архив сохранений. Следующая пойдёт лучше.»
3. **Факт риска**: красным — только `fact.title` (реальная причина `defeat_reason`), дальше деталь `fact.text` с суммой на счёте.
4. **Два совета** (`fact.tips`, не больше двух).
5. **«Новая игра»** — главная; **«К сохранениям»** · партия в архиве — вторая.
6. Необязательный отзыв.

## Инварианты

- Полноэкранная доска (`--mq-board`), не лист поверх игры; колонка до 480px, safe-area сверху и снизу.
- Роли цвета ADR-014: золото — финиш и деньги, фиолетовый — действие, красный — факт риска и суммы расходов решений DC-08, зелёный — заработок; красный фон — только у факта риска. Тёмная тема — те же токены v2.
- Лексикон: «ход», «Завершить ход»; без «месяц», «cash», служебных терминов и КАПС-лейблов.
- Данные и тексты — из payload `run_finale` (`game/api/app/game/run_finale.py`), не хардкод в UI.
- Блок «Попробовать другого персонажа» после победы снят: выбор жизни — через «Новая игра».

## DC-08 · «Что решило партию», A · Чек (2026-11-11)

- [Утверждение PO](decisions-round/APPROVED.md): A для победы и поражения; [макет](decisions-round/index.html).
- Локально перенесён в `MqxRunFinale`, демо — `#/dev/mqx` и fixture `game/web/e2e/run-finale.html`.
- Победа: блок между показателями и кнопками. Поражение: между советами и кнопками. Отзыв остаётся ниже кнопок.
- До трёх строк, порядок и состав — из API `decisions`; UI не выбирает порог и не ранжирует.
- Пустой/отсутствующий массив скрывает блок. Оценка — «≈», расходы — «−», заработок — «+». Знак доступен скринридеру.
- Подпись `N мес. расходов` использует `monthly_burn` из API; при нуле/отсутствии базы скрыта. Это масштаб суммы, а не условие отбора.
- Красный допустим для отрицательных сумм, зелёный — для заработка; фон списка нейтральный, красный фон остаётся только у факта риска. Это уточняет цветовой инвариант выше для нового блока.
- Пояснения — токен `--mq-fs-caption` (12 px), вместо 11,5 px статичного макета.
- По поручению PO DC-08 выполнен параллельно DC-06. После отчёта PO предварительно принял порог **1× среднего регулярного дохода** («Давай пока 1х», 2026-11-11); backend использует историю закрытых ходов с восстановлением пропущенных зарплат. Подпись масштаба в A остаётся в месяцах расходов. Прежнее ранжирование/агрегирование вложений сохранено.

## Осознанные отличия prod от screens-round

- Размеры — токенами prod (`--mq-fs-*`, `--mq-sp-*`), кнопки ≥44–48px (touch), поэтому чуть крупнее макета.
- «Отправить отзыв» — фиолетовая ссылка (действие по ADR-014), в макете `--ink-soft`; пока поле пустое — неактивна и серая.
- «Отправить отзыв» есть и на поражении (в макете не нарисована, но отзыв нужен в обоих исходах).
