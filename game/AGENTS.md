# ТВОЙ ХОД · GAME

Открывай эту папку как продуктовый проект Codex. Общие границы —
[AGENTS](../AGENTS.md), карта — [ARCHITECTURE](ARCHITECTURE.md).
Начни с [README](README.md) и затронутой spec/плана в docs; PLAN не загружай.

PWA/web primary, Telegram secondary. Одна экономика, один цикл периода, один API.
Контент событий — `data/events/mvp11/`, baseline SQL — DDL-only.
Финансы используют `../shared/packages/fincore`; адаптеры остаются в api.
Новый layout/карточка/CTA/sheet: концепт-картинка → обязательный Design Lab на MQX → явное утверждение превью человеком → подключение к игре.
Мелкие layout-neutral исправления — по
[DESIGN_WORKFLOW](web/src/components/mqx/DESIGN_WORKFLOW.md).
Исходники CSS/ассетов — design, экспорты обновлять генераторами.
В рабочих разделах документации и дизайна храни только актуальные материалы.
Заменённые и закрытые материалы переноси в архив по
[правилу актуальности](docs/README.md#актуальность-и-архив).

Общие навыки наследуются из корня; игровые находятся в `.agents/skills` этой папки.
Профиль задач — [GAME processes](docs/engineering/CODEX-PROCESSES.md).
Навыки: delivery для обычных задач; game-economy для экономики; event-authoring /
event-audit для контента; mqx-design / frontend-implementation для UI;
api-contract-change, db-migration, review-change, verify-change — по области.
Существенная экономика требует 30–40 периодов и осмысленного balance diff.
Review экономики без зелёного backend pytest — NEEDS REVISION.

Проверки из корня продукта: `npm.cmd run check`; runner выбирает `game/.venv`.
Адресно из api: `../.venv/Scripts/python.exe -m pytest -q` после установки среды
продукта; другой runtime задаётся явно через `PROJECT_PYTHON` / `E2E_PYTHON`.
Из web: `npm.cmd run test:unit`, `npm.cmd run build`, `npm.cmd run check:guardrails`;
Playwright для критичного UI. Review агента или тест не заменяют approval человека.
Сохраняй пользовательские изменения; не читать env, credentials и реальные анкеты.

Актуальное визуальное направление GAME — [«Финансы как игра»](design/system/CURRENT_STYLE.md). Для новых макетов используй [утверждённый логотип и его форматы](design/system/assets/Logos/README.md).

Канон игрового меню и общего таббара — [Меню · утверждено](design-lab/finance-game-round/MENU_APPROVED.md). Используй общие компоненты BrandLogo и BottomGameNav.

Канон маскота — [золотая Монетка и девять утверждённых поз](design-lab/mascots/APPROVED.md). В игре используй `Monetka` и `MonetkaAvatar` с позой по сценарию. Игровые экспорты берутся из `design/system/assets/Monetka/poses/`.

Ссылки на материалы проекта в ответах давай как ссылки на файлы с абсолютным
путём. Якоря вида `#раздел` в ссылках на файлы не работают. Чтобы указать нужное
место, назови раздел рядом со ссылкой.

Локальные превью: перед передачей ссылки запусти сервер, открой точный маршрут
в браузере, которым сможет воспользоваться человек, и проверь заголовок
экрана и основное действие. Ответ HTTP 200 сам по себе не проверяет маршрут
с hash. При тайм-ауте проверь процесс, адрес и порт, исправь причину и повторно
открой страницу. Если встроенный браузер Codex не видит loopback, проверь и
открой страницу в обычном браузере на машине с сервером. Оставь сервер
запущенным и проверь его перед ответом. Если открыть превью не удалось,
сообщи конкретную ошибку и не выдавай ссылку за рабочую.

Домашний стенд GAME: назначение, текущий статус и подключение по SSH описаны
в [HOME_SERVER](docs/ops/HOME_SERVER.md). Проверяй фактический доступ из своей
сессии перед удалённой работой. Для стенда используй отдельные тестовые данные.
