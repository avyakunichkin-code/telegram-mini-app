# ADR-018 · Единый источник решений для каждого слоя GAME

## Контекст

Утверждение Капитала было записано в решении экрана и реестре дизайна, но
общий README продолжал предлагать выбрать старый вариант. Повторение статусов
в навигации создаёт несколько конкурирующих ответов.

## Решение

Для каждого слоя GAME назначается один источник текущих утверждённых решений;
точки входа перечислены в [карте источников](../README.md#источники-решений-по-слоям).
Источник может содержать краткие решения и ссылки на детальные контракты. У
каждого решения в источнике одна действующая запись: область, решение, статус,
ссылка на основание и при необходимости на проверку. История остаётся в ADR,
архиве или Git, а не конкурирует с текущей записью. Если решение затрагивает
несколько слоёв, один слой владеет его смыслом; остальные ссылаются на него.

Новое решение сначала фиксируют в источнике своего слоя в том же изменении,
указывая принятое человеком решение, когда оно требуется. После этого
актуализируют непосредственно затронутые spec, ссылки и потребителей. Остальные
документы ссылаются на источник и не создают независимое утверждение. При
расхождении между документами для утверждённого решения берут источник слоя,
называют расхождение и исправляют затронутый документ. Дата сама по себе не
заменяет решение. Неизвестное решение не выдумывают: отмечают пробел и находят
основание; нерешённый конфликт передают владельцу.

## Границы

Источник решения описывает **что утверждено**, а код и тесты показывают **что
фактически реализовано**. При расхождении их не объявляют взаимозаменяемыми:
фиксируют оба факта и отдельно решают, нужно менять реализацию или пересмотреть
решение. Это сохраняет действующую иерархию поведения из CONVENTIONS C-1.
Preview, утверждение и внедрение дизайна — разные статусы; агент или тест не
заменяет согласование человека. Для решений общего ядра и границ продуктов
источник находится в корневой документации, не в GAME. Каталоги контента,
схемы и API имеют свои исполняемые источники: запись решения на них ссылается,
но не копирует данные или контракт целиком.

## Варианты и последствия

Копировать все решения в один большой документ для всего проекта отвергнуто:
слои имеют разных владельцев и разные проверки. Оставить дубли статусов в
каждом README отвергнуто: они расходятся. Цена выбранного подхода — при каждом
решении поддерживать запись слоя и устранять обнаруженные расхождения. Наличие
указателя не доказывает полноту переноса старых решений и не меняет поведение.

## Проверка и пересмотр

Для изменённого решения проверить запись слоя, основание, ссылки, связанные
контракты и применимые тесты. Если источник не покрывает тему, сначала добавить
подтверждённое решение или явно отметить пробел. Пересмотр — новым ADR с
миграцией указателей; исторические решения и подтверждения сохраняются.
