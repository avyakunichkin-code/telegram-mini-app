# ADR-017 · Один стиль и три области компоновки GAME

Широкий и компактный режимы игры используют одну модель партии и компоненты MQX. Лендинг представляет игру и собирается отдельно. Если каждая область задаёт собственную палитру общих элементов, одинаковые действия начинают выглядеть по-разному. Если один CSS описывает все компоновки без границ, локальная правка разметки может затронуть соседний экран.

## Решение

[Реестр дизайна](../../design/system/design-canon.json) задаёт одно активное направление и его ревизию. В нём три области: компактная игра, широкая игра и лендинг. Telegram использует компактную игровую оболочку с адаптацией под WebView. У каждой области своё утверждение компоновки и отметка о применённой ревизии. Смена общего направления утверждается один раз. Для каждой области отдельно проверяется результат переноса.

- Общие компоненты и семантические токены задают цвет по роли, форму, типографику и состояния. Логотип и образ персонажа имеют общий источник. Допустимые сюжетные иллюстрации персонажа фиксируются как варианты.
- Игровая компоновка управляет сеткой, порядком, местом и доступным размером компонентов. Стили широкой компоновки ограничиваются её оболочкой. Для игровых действий обе компоновки используют одинаковые варианты MQX.
- Лендинг определяет собственные секции, маркетинговые действия и композицию иллюстраций. Он получает согласованные ассеты из дизайн-системы. Игровой вид интерактивной демонстрации сверяется с утверждённым экраном. Маркетинговый блок становится игровым компонентом после отдельного утверждения.

## Проверка и перенос

Первый срез охватывает логотип, Студента и «Завершить ход». Генерируемые таблица и каталог читают общий реестр. Проверка канона выявляет несуществующие ссылки, неизвестные области и несовпадение документа с реестром. При локальной правке широкой компоновки сравниваем компактный экран до и после на одинаковых данных. При правке общего элемента сверяем зарегистрированных потребителей.

При проблеме откатываем компоновку конкретной области или её подключение к общей ревизии по отдельности. Решения, которые заменены новой ревизией, сохраняем в архиве со ссылкой на замену.
