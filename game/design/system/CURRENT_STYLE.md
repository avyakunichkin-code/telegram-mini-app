# Дизайн приложения

## Утверждённый дизайн для восстановления

Источник решений — [«Спроектировать браузерную игру»](https://chatgpt.com/s/cx_6af8ba4f30f08191b87c60c738007620). В чате зафиксированы выбор и внедрение в прежней рабочей копии. Ниже указано состояние в текущей ветке.

| Область | Утверждено | Текущая ветка |
|---|---|---|
| Общий стиль | Pocket Board A «Игровой пульт» для игровых вкладок, событий, финансовых окон и итогов | На Главной подключена палитра Pocket Board G. Остальные экраны используют «Чернильный край». Сохранившийся [CSS превью](../../landing/site/game-preview/runtime.css) содержит правила Pocket Board. |
| Главная | Карта хода Г: логотип с подписью внутри карты, баланс левее, крупный персонаж, завершение на всю ширину, прогноз списаний снизу. События, зарплата и компактные потребности в верхней части экрана, компактная цель ниже. | В игровой карте восстановлены логотип, баланс, портрет, кнопка и прогноз. Зарплата, потребности и цель пока используют прежнюю компоновку. Референсы: [карта хода Г](../../landing/site/game-preview/TurnCard.html) и [денежный блок](../../landing/site/game-preview/MoneyTiles.html). |
| Помощь Монетки | Вариант Б: Монетка в верхнем блоке, контекстная помощь по нажатию, без разделяющей строки и сдвига при получении зарплаты. Эмоции соответствуют зарплате, событиям, готовности завершить ход и финансовому риску. | Подсказка открывается в диалоге из верхнего блока. Используется утверждённый объёмный аватар. Набор эмоций ещё предстоит восстановить. |
| Старт | Гостевой старт А «Твои решения. Твой финансовый опыт». Короткое обучение первого хода и добровольное закрепление партии за аккаунтом после первого итога. | В API есть гостевые маршруты. Гостевой сценарий и экран А в web нужно восстановить и проверить сквозным сценарием. |
| Иллюстрации ролей | Утверждённые портреты v3 с лендинга | В игре подключены обычные портреты всех четырёх ролей. Победные иллюстрации с кубком используют прежний набор. |

Pocket Board A задаёт визуальный стиль приложения. Г и Б относятся к отдельным решениям Главной. Превью лендинга содержит условные данные и пассивные элементы. В игровой реализации для этих же элементов нужны действующие обработчики, реальные расчёты и проверка сценариев.

## Состояние рабочей копии · 14.11.2026

Базовые стили приложения — «Чернильный край». На Главной поверх них работает палитра Pocket Board G для светлой и тёмной тем, сливовая карта хода, золотая кнопка и материалы событий и зарплаты. Полный экран Г пока не восстановлен: открыты порядок блоков, компактность потребностей и цели, эмоции Монетки и браузерная сверка с эталоном.

Редактируемый runtime CSS находится в `game/design/system/runtime/`. Пути `game/web/src/index.css` и `game/web/src/styles/` — его проверяемые экспорты. Иллюстрации ролей v3 находятся в `assets/Characters/landing-v3/`, объёмная Монетка и аватар — в `assets/Monetka/`.

## Цепочка источников

1. `runtime/styles/tokens.css` — токены «Чернильного края»: `--mq-ink-w`, `--mq-ink-line`, `--mq-ink-drop`, `--mq-ink-off`, `--mq-ink-off-s` (в тёмной теме край и тень — `--mq-board-ink-faint`). Те же токены — в `tokens.json` дизайн-системы.
2. `runtime/styles/mqx/*.css` — правила стиля в CSS своего блока: `board.css` (Главная), `finance.css` (Капитал, листы и подтверждение — последним разделом файла), `events.css`, `juice.css` (итог хода), `analytics.css`, `pregame.css` (вкладка Меню), `run-finale.css`, `guidance.css` (подсказка онбординга), `shell.css` (таббар).
3. `game/design-lab/board-game/APPROVED.md` — инварианты стиля (обводка, цветная и чернильная тень, одна рамка на уровень) и история: выбранный A, карта хода K1, окна `ink-sheets-round`, доработка и ★ по `ink-decision-round`.
4. В этой дизайн-системе — `components/InkEdge/README.md`, `preview.html`, классы `.th-ink` в `components/bundle.css`: те же правила на примерах `th-*`.

До 2026-11-02 стиль был пробным слоем `styles/mqx/ink.css` под `:root[data-mqx-style='ink']` с переключателем `utils/mqxStyle.js`; слой влит в CSS блоков, переключатель удалён.

## Превью и лендинг

`ink-preview.html` показывает пример InkEdge. Адаптер `components/InkEdge/examples.css` применяет правила к трём базовым примерам; переменные `--mq-ink-*` берутся из `tokens.css`, отдельный `runtime-ink.css` больше не экспортируется. Образцы по-прежнему помечены как примеры системы, не скриншоты production.
