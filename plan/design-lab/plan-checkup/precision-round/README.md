# P3-11 · Точность данных · A / B

2026-11-07. **A утверждён владельцем и переносится в мастер.** Решение: «Да, делаем А»; [область утверждения](APPROVED.md), [перенос и проверки](../../../docs/audits/2026-11-07-precision-ui.md). B остаётся сравнительным вариантом. Существующий отчёт B2/C1 не меняется.

- **A · Рядом с полем — рекомендация:** короткая подсказка у суммы; предупреждение рядом с диапазоном; общая оценка в шапке каждого раздела. Меньше вертикального шума.
- **B · Что уточнить:** отдельная карточка с приоритетным разделом и кнопкой перехода. Удобнее после быстрого старта, когда нужно понять, куда идти, но добавляет блок над вводом.

В обоих вариантах одинаковые синтетические данные и расчёт: доход 120 000 точно, расходы 20 000–100 000, накопления 270 000 точно, оценённый кредит с платежом 30 000. Это фрагмент мастера из четырёх разделов, влияющих на текущую оценку; полный мастер, анкета и редактирование договора кредита не входят в этот раунд.

## Смысл оценки

Логика повторяет `plan_api/analysis/adapter.py::precision`: вес диапазона — max; уточнённым считается min > 0 и max/min ≤1.1. Вес кредита — платёж; estimated снижает оценку. Нулевые веса исключены. Пороги: 50% и 85%. Пустой набор обозначен «Нет сумм для оценки», не низкой оценкой семьи.

Предлагаемая подсказка: раздел с наибольшей суммой неточных весов, а не с максимальным отношением max/min. При равенстве — стабильный порядок доходы/расходы/накопления/долги. Это приоритет уточнения по существующей шкале, не измерение ошибки прогноза и не обещание, что одно поле даст определённый результат. Сам API расчёта не меняется.

Широкий диапазон: max/min >3; ровно 3 предупреждения не даёт. При min=0 и max>0 — текст о широком разбросе без деления на ноль. Оба нуля не считаются широким диапазоном. Предупреждение не запрещает сохранение; отрицательные/перевёрнутые/пустые границы — ошибка ввода. Оценка в шапке — предварительная по текущему вводу; отчёт после сохранения получает своё значение от сервера.

В примере исходная доля 75%; точные расходы 60 000 дают уточнённую оценку, но оценённый кредит остаётся следующим кандидатом. Изменение платежа не делает оценённый остаток кредита точным: нужны условия договора. Никакого ложного автоматического снятия estimated.

## Состояния и проверка

Обычное, нет сумм, нулевая граница, saving/disabled, ошибка с сохранением ввода и повтором, офлайн. Переключатели в серой полосе относятся только к lab. Всё — в памяти страницы, без запросов и данных пользователей.

Команда из корня: `node plan/design-lab/plan-checkup/precision-round/verify.mjs`. Проверка pure model и A/B на четырёх ширинах; результаты/снимки в `qa/`. Backend/UI production suites не нужны до переноса: приложение и сервер не менялись. Самопроверка не заменяет утверждение владельца. После выбора — перенос с unit-тестами FE и проверкой согласованности с серверной оценкой.
