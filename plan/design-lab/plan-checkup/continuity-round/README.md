# P3-03 · прошлый шаг в новом чекапе

Статус: **утверждён 3 / C «Мост между шагами»**, 2026-11-06. Слова владельца:
«Давай выберем 3 Мост между шагами». Смотреть через [хаб](../../../../game/design-lab/index.html),
раздел «ТВОЙ ПЛАН». Раунд продолжает утверждённый билет действий P3-02 и визуальный
язык журнала с полями P3-08. Реализация — PreviousStepBridge.jsx/previous-step.css;
данные — previous_steps в API отчёта. Канон — [APPROVED](../APPROVED.md).

- **1 / A · Короткая строка.** Минимум места над новым шагом. Статус и метрика рядом,
  остальные прошлые шаги раскрываются. Самая спокойная подача.
- **2 / B · Заметка на полях (рекомендация).** Короткая заметка прикреплена к текущему
  билету. Прошлое видно как контекст, новый шаг остаётся главным. Остальные шаги ниже.
- **3 / C · Мост между шагами.** Прошлый и новый шаги стоят рядом; на телефоне —
  последовательно. Самая явная связь, больше места на странице.

Одинаковые данные: прошлый first_cushion отмечен done (3/3 действий); подушка
в сохранённом октябрьском отчёте 0,4 месяца, в ноябрьском 1,2; следующий шаг —
взносы в подушку по 12 000 ₽/мес. Текущий свободный остаток 24 000 ₽, расходы
100 000 ₽/мес. Другие прошлые шаги: stop_deficit без отметок, stress_fail dismissed.
При запасе ниже месяца в состояниях decline/same текущий пример показывает first_cushion по действующим правилам. Текущий билет в lab — контекст для выбора; при переносе сохраняется утверждённый StepActions.
Никакой текст не утверждает, что рост подушки вызван именно выполнением шага.

Состояния: done, partial, suggested, dismissed, manual done, без изменения метрики,
уменьшение подушки, отсутствующая старая метрика, разные версии, первый чекап,
loading, error/retry, offline/disabled, legacy шаг без actions. При первом чекапе
блок истории отсутствует. Прошлый статус не меняется из нового отчёта; новый шаг
начинается с собственных отметок. Открытие прошлого отчёта демонстрируется отдельно.

## Контракт внедрения

- Использовать parent_checkup_id, а не произвольный последний отчёт пользователя.
- Все 1–3 шага родителя доступны; lab выносит отмеченный first_cushion как основной
  пример, остальные в disclosure. Выбор основной карточки должен быть явным правилом
  адаптера, без предположения, что неотмеченное предложение было принято человеком.
- Читать сохранённый отчёт родителя плюс подтверждённые статусы его шагов.
  В черновике контекст может обновляться; при завершении нового отчёта зафиксировать
  прошлые статусы и метрики внутри нового снимка, чтобы поздняя отметка старого шага
  не переписывала историю уже завершённого чекапа.
- Первым трём сравниваемым метрикам соответствуют реальные поля: подушка —
  metrics_base.safety_fund_months, DTI — metrics_base.dti_percent, остаток —
  free_cashflow. Дельта DTI — п. п. Отсутствующее значение — null, не 0.
- Для правил без подходящей метрики не выдумывать числовой результат. Версии
  правил/ядра сравнивать явно. Источники должны принадлежать household пользователя;
  старый отчёт не пересчитывать. Отсутствующий/недоступный родитель — понятное состояние.
- События аналитики, правила рекомендаций, пороги и общий ui-kit не расширяются.

Синхронизация базы: из корня `node plan/design-lab/plan-checkup/continuity-round/sync-lab.mjs`.
lab-base.css генерируется; CSS и JS раунда локальные, без внешних ресурсов.
