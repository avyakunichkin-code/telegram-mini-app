# P3-09 · события прохождения · 2026-11-05

Очередь владельца: P3-02 → P3-09 → P3-08 → P3-12. Этот срез закрывает P3-09
в локальном прототипе; не создаёт отчёт метрик P3-10 и не меняет UI.

## Результат

- Все 11 утверждённых имён событий проходят единую серверную валидацию в
  `plan_api/analytics.py`, включая вызовы `Repo.track`. Схемы props закрыты:
  фиксированные enum/ключи вместо произвольного текста, неизвестные поля запрещены.
- `quick_done.duration_seconds` и `checkup_completed.duration_seconds` считаются
  по серверному created_at чекапа, без клиентских часов. Возобновление черновика
  не сбрасывает начало; паузы включены. Первый quick и каждый раздел фиксируются
  один раз на чекап с устойчивым id события и ON CONFLICT; следующий чекап независим.
- `report_viewed` фиксируется и при возврате отчёта из complete, включая
  идемпотентную выдачу сохранённого результата. Это выдача API, не факт прочтения.
- `step_action_done` из P3-02 сохранён: rule_key и key действия, без текста/сумм.
- При удалении аккаунта его события удаляются немедленно в той же транзакции;
  остаётся только анонимное account_deleted с пустыми props. Другие пользователи
  не затрагиваются. Последующий purge поддерживается.
- POST /api/events сужен: текущих frontend-потребителей нет; поддержан только
  типизированный report_viewed. Попытки клиентом записать milestones/длительности
  возвращают 422, нет JWT → 401. Финансовые поля любого размера → 422.

### Уточнение критерия плана

Старый критерий «любое число > 1000 → 422» конфликтовал с временем полного чекапа:
20 минут — 1200 секунд. До правки это расхождение названо владельцу; применена
строгая схема по назначению поля. 1500 секунд от сервера допустимы, поле amount
даже со значением 1 запрещено. Дополнительные события или финансовые props
не вводились. Схема SQL и исходные сохранённые расчёты не менялись.

Backend: реальные маршруты производят все утверждённые события; фиксированные
часы подтверждают 180/1500 секунд, повторы, второй чекап; проверены auth, строгие
типы, неизвестные поля, свободный текст, суммы 5 и 150000, защита внутренних
производителей, немедленное удаление и purge. Первая проверка выявила ошибку
тестовой фикстуры (now_iso в auth принимает аргумент): фикстура исправлена,
финальный полный прогон зелёный. Тесты с loopback выполнены вне sandbox.

Frontend-файлы не менялись: существующие api.quick/api.putSection/api.complete/
api.report и PATCH действий проверены на реальном локальном API. Отдельные
unit/build/guardrails Game не запускались: код интерфейса и игра не затронуты.
AI-конфигурация не менялась; независимого агентского ревью не было.

Ограничения: длительность календарная, не активное время; старые события без
duration не заполняются задним числом. Это не завершение юридического допуска,
P2 целиком, внешнего деплоя или P3-10. Следующий срез очереди — P3-08.
