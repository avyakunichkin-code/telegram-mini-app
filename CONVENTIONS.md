# Свод принципов — ТВОЙ ХОД

Это не стиль и не чеклист «как писать код». Здесь выносится вердикт: работа **соответствует** или **нарушает**. Нарушение — предмет правки, не вкусовщины.

**Среда агента — Cursor** (rules, skills, subagents). `CLAUDE.md` — историческое имя индекса, не конституция Anthropic и не слой выше этого файла.

## Иерархия

```
CONVENTIONS.md                         ← вердикт: почему так
  → ADR, SPEC, DOCUMENTATION_SYSTEM    ← что решили
  → .cursor/skills + .cursor/rules     ← как делать в Cursor
  → CLAUDE.md                          ← индекс для агента
  → README                             ← вход для человека
```

`CONTRIBUTING.md` в репозитории нет и не заводится этим срезом: точечные «как» живут в скиллах и rules.

Конфликт принципа и правила — баг того же PR: правило приводится к принципу, либо принцип пересматривается явно (см. «Как менять этот файл»). Оставить расхождение нельзя.

Идентификаторы не переиспользуются. Снятые id — в конце файла.

## C-X · Принцип — гипотеза, а не догма

**Ограничение.** Столкнувшись с тем, что действие нарушает принцип, сначала проверь сам принцип: не даёт ли он неверный вердикт. Оснований для пересмотра ровно три: (1) неверный вердикт — помечает нарушением то, что им не является, или пропускает то, что является; (2) цена оказалась иной, чем в «Платим»; (3) основание исчезло — изменилась среда. «Соблюсти дорого» основанием **не** является: цена названа в принципе, платить её и есть соблюдение. Обратное тоже нарушение: соблюсти формально там, где принцип даёт бессмысленный вердикт, и промолчать.

**Объект вердикта.** Запись принципа в этом файле; PR, который «зеленит» гейт ослаблением принципа; спор «это нарушение или нет».

**Вопрос ревью.** Есть ли одно из трёх оснований — или мы просто не хотим платить названную цену?

**Нарушение выглядит так.**
- Снять XP персонажа из UI, оставив `event_tier` от «уровня» в коде, и назвать это «временным исключением без срока» ([ADR-003](docs/decisions/ADR-003-remove-character-progression.md) закрыл как раз такой разъезд).
- Ослабить формулировку C-2, чтобы `/complete-period` снова отвечал 200 «пока фронт не зовёт».
- Объявить аудит [`docs/audits/`](docs/audits/README.md) каноном, потому что «свежее, чем spec».

**Покупаем.** Свод остаётся живым: его можно оспорить случаем, а не обойти молча.

**Платим.** Пересмотр занимает время человека; агент не имеет права переписать принцип «по ходу задачи».

**Порождает правила.** Раздел «Как менять этот файл» ниже; [`.cursor/skills/_shared/clarify-first.md`](.cursor/skills/_shared/clarify-first.md) (STOP при конфликте spec vs код).

**Соответствие.** Обязательно.

**Якорь.** `py -3 scripts/check_conventions.py` — у каждой записи полный набор полей; статус «Пробное (до ГГГГ-ММ-ДД)» с прошедшей датой — ошибка; идентификаторы из раздела «Снятые» не встречаются как действующие заголовки `## C-…`.

## C-Y · Решение человека — предмет разбора, а не эталон

**Ограничение.** Решение, поступившее от человека (постановка, подход, число баланса, формулировка урока), исполняется потому, что выдержало разбор, а не потому, что его высказал человек. Расхождение называется **до** начала работы, вместе с альтернативой и её ценой. Подтверждённое решение исполняется полностью; согласие «в душе» не требуется: несогласие — одна строка в журнале, спор не возобновляется.

Это **не** правило «всегда предлагай». Если решение верное и замечаний нет — предлагать нечего. Возражение без альтернативы — шум. Работа не ждёт обсуждения там, где ответ не нужен. Блокирующий вопрос — только если любое допущение делает результат негодным или небезопасным. Вкусовщина при живой конвенции — не предмет.

**Объект вердикта.** Постановка задачи; выбранный агентом путь; запись в [`docs/conventions/reviews.yaml`](docs/conventions/reviews.yaml).

**Вопрос ревью.** Названо ли расхождение до работы, с альтернативой и ценой — или агент молча принял (или молча «улучшил») решение?

**Нарушение выглядит так.**
- Молча собрать полный «учебник принципов» с двенадцатью пунктами и blocking hook, хотя в репозитории уже есть ADR, скиллы и иерархия docs — без предложения короткого слоя (этот срез: разбор [CY-2026-09-09-slim-layer](docs/conventions/reviews.yaml)).
- «Сделать как сказали» при явном конфликте с ADR-013: снова чинить Plan UI после решения «только Game».
- Спорить о порядке полей в YAML, когда [event-balance-rules](.cursor/skills/create-event/event-balance-rules.md) уже задаёт канон — вкусовщина.

**Покупаем.** Ошибки и дыры в постановке ловятся до diff; утверждённое не переигрывается каждым агентом.

**Платим.** Журнал не ловит молчание: пропущенный разбор в него просто не попадает (см. реестр отклонений).

**Порождает правила.** [`.cursor/skills/using-agent-skills/SKILL.md`](.cursor/skills/using-agent-skills/SKILL.md) § «Push Back When Warranted»; [`.cursor/skills/_shared/clarify-first.md`](.cursor/skills/_shared/clarify-first.md); [`.cursor/skills/_shared/delivery-workflow.md`](.cursor/skills/_shared/delivery-workflow.md).

**Соответствие.** Обязательно.

**Якорь.** `py -3 scripts/check_conventions.py` — журнал `docs/conventions/reviews.yaml`: возражение без `alternative` отклоняется; `accepted`/`partial` без `repo_trace` — ошибка; закрытая запись (`accepted`/`partial`/`rejected`/`withdrawn`) без `decision` — ошибка. Скрипт печатает, сколько разборов за 90 дней и в скольких `decision_changed: true`.

## C-1 · Один канон при конфликте

**Ограничение.** Поведение продукта определяется в таком порядке: **код + тесты** → `docs/specs/features/SPEC_*.md` → `docs/foundation/SPEC_PRODUCT.md` → `docs/vision/ideas/`. Бэклог — приоритет, не спецификация. Аудит в `docs/audits/` — снимок на дату, не канон, пока выводы не утверждены в spec/ADR/backlog. Агент и человек не имеют права чинить «по более свежему ощущению», игнорируя верхний слой.

**Объект вердикта.** PR, idea, audit, agent session, расхождение docs vs код.

**Вопрос ревью.** Если два источника спорят — взят ли верхний слой иерархии, или нижний выдан за истину?

**Нарушение выглядит так.**
- Трактовать [QA-аудит 2026-09-07](docs/audits/qa/2026-09-07-mechanics.md) (status: DRAFT) как обязательную спеку и плодить фичи «по аудиту» без plan/ADR.
- Держать в `SPEC_PRODUCT` «ворота победы с 7-го периода сняты», а в [`GLOSSARY.md`](docs/foundation/GLOSSARY.md) оставлять старую формулу 3× подушки как prod-победу без пометки legacy.
- Писать код по `docs/vision/ideas/` в обход утверждённого spec (конвейер [DOCUMENTATION_SYSTEM](docs/DOCUMENTATION_SYSTEM.md) §3–4).

**Покупаем.** Один ответ на «как на самом деле работает игра»; агенты не разъезжаются по слоям docs.

**Платим.** Устаревший spec надо чинить явно, а не «побеждать» его кодом втихую; идея не становится законом от того, что она красноречива.

**Порождает правила.** [`docs/DOCUMENTATION_SYSTEM.md`](docs/DOCUMENTATION_SYSTEM.md) §3; [`.cursor/skills/_shared/game-lexicon.md`](.cursor/skills/_shared/game-lexicon.md); [`docs/audits/README.md`](docs/audits/README.md); [`.cursor/rules/tvoy-hod-router.mdc`](.cursor/rules/tvoy-hod-router.mdc).

**Соответствие.** Обязательно.

**Якорь.** `py -3 scripts/check_conventions.py` — в `docs/DOCUMENTATION_SYSTEM.md` есть упорядоченный список конфликта; в `docs/audits/README.md` есть явное «не канон». Поведенческий «агент следовал аудиту как spec» скрипт не ловит (реестр отклонений).

## C-2 · Один продукт — одна экономика, одна поверхность

**Ограничение.** ТВОЙ ХОД — **одна** игра: один цикл месяца, одна экономика, один SPA, один API. Нельзя заводить второй пайплайн тех же денег, второй режим как отдельный продукт или второй канал как отдельную экономику. Различия каналов — layout/auth/shell, не правила периода. Исторические развилки (Plan, TMA-как-единственный-gate, legacy close) либо сняты, либо явно мертвы (410 / 400 / archived skill), а не «на всякий случай живы».

**Объект вердикта.** Эндпоинт, `save_kind`, release skill, форк фронта, второй `process_period_end`.

**Вопрос ревью.** Появился ли второй способ сделать то же самое с другими правилами денег или победы?

**Нарушение выглядит так.**
- `POST /api/game/period/complete-period` двигал месяц **без** `process_period_end` (QA C2; закрыто PR-03 → 410). Канон close: `POST /api/game/time/next`.
- Второй save `plan` как «MVP 2.0» параллельно Game ([ADR-013](docs/decisions/ADR-013-game-only-drop-plan-mode.md) — cancelled; эпик GO вырезает остатки).
- Release gate только `/release-tma` при каноне PWA/web primary ([ADR-012](docs/decisions/ADR-012-primary-channels-pwa-web-over-tma.md)).
- Форк экономики «под Telegram» vs «под браузер».

**Покупаем.** Игрок и агент видят одни правила; QA не размножает матрицу «в каком клиенте какая физика».

**Платим.** Legacy-пути нельзя оставить «тихим запасным»; вырезание (GO) дороже, чем вовремя сказать «нет».

**Порождает правила.** [`SPEC_PRODUCT.md`](docs/foundation/SPEC_PRODUCT.md) §1.1 и core loop; [ADR-012](docs/decisions/ADR-012-primary-channels-pwa-web-over-tma.md); [ADR-013](docs/decisions/ADR-013-game-only-drop-plan-mode.md); [`backend/tests/integration/api/test_complete_period_gone.py`](backend/tests/integration/api/test_complete_period_gone.py); skill `release-web`.

**Соответствие.** Обязательно.

**Якорь.** `py -3 -m pytest tests/integration/api/test_complete_period_gone.py tests/unit/period/test_complete_period_gone.py -q` (из `backend/`); гейт свода проверяет, что эти файлы существуют. Каналы: в `docs/foundation/SPEC_PRODUCT.md` есть ADR-012.

## C-3 · Песочница честна к миру, которому учит

**Ограничение.** Игра одновременно модель денег и продукт про грамотность. Нельзя: (1) выдавать ставки и доходности финансовых **продуктов** (кредит, вклад, облигация, страховка, ипотека) как «как в жизни», если нет названного источника **или** явной пометки «условность игры»; (2) учить осторожности, эксплуатируя импульс — микрозайм / «до зарплаты» как решение, казино и азарт как награда или луп, монетизация «ещё одна попытка»; (3) давать персональные финансовые рекомендации или имитировать совет («инвестируй в…», обещание доходности). Пропуск зарплаты до закрытия месяца — **допустимый учебный кол**, не тёмный паттерн: это названо в продукте. Цена кофе в событии YAML не обязана иметь источник ЦБ — это не ставка продукта.

**Объект вердикта.** Шаблон обязательства/вклада/страховки; копирайт события и UI; аналитика-прогноз; механика монетизации.

**Вопрос ревью.** Игрок унесёт из этого экрана представление о мире, которое мы не готовы подписать — или мы явно сказали, что это условность / не совет?

**Нарушение выглядит так.**
- Дефолт `annual_rate_percent=12` в админ-создании каталога «с потолка» ([`catalog_create_payload.py`](backend/app/admin/catalog_create_payload.py)) без пометки условности.
- Сюжет микрозайма как спасения кассы (запрет [TARGET_PLAYER §3](docs/foundation/TARGET_PLAYER_AND_SESSION.md); старый набросок в `QUESTIONNAIRE.md`).
- Прогноз аналитики как обещание без disclaimer ([SPEC_ANALYTICS](docs/specs/SPEC_ANALYTICS.md) это уже требует; в UI дисклеймера «не совет» **ещё нет** — см. отклонения).
- IAP «купи вторую жизнь после поражения» — в продукте нет и не заводится.

**Покупаем.** Образовательный эффект не превращается в дезинформацию и не противоречит уроку.

**Платим.** Не каждое число в YAML — предмет источника; граница «продукт vs быт» требует суда человека. Полного дисклеймера в клиенте пока нет.

**Порождает правила.** [`TARGET_PLAYER_AND_SESSION.md`](docs/foundation/TARGET_PLAYER_AND_SESSION.md) §3–4; [`SPEC_PRODUCT.md`](docs/foundation/SPEC_PRODUCT.md) §1 педагогический тезис; create-event [event-balance-rules](.cursor/skills/create-event/event-balance-rules.md) (trade-off, не «бесплатный плюс»).

**Соответствие.** По умолчанию.

**Якорь.** `py -3 scripts/check_conventions.py` — в `data/events/`, `frontend-react/src/`, `landing/src/` запрещены игроку-видимые формулировки из словаря (микрозайм как решение, казино/азарт-награда, «инвестируй в», «гарантированн* доходно»). Поле «источник ставки» в каталоге шаблонов **ещё не схема** (реестр отклонений).

## C-4 · Числа и контент — в данных, код — правила применения

**Ограничение.** Каталог событий, пороги победы шаблона, ставки и блюпринты старта живут в **данных** (YAML, `victory_config_json`, `game_starter_templates`). Код знает, *как* применить эффект, закрыть месяц, выбрать из пула. Второй канал тех же чисел (SQL INSERT контента, магические пороги «только в Python», XP/level персонажа как прогрессия) — нарушение. Константа движка вроде «два события на период» или «три негативных периода до поражения» — правило применения, не контент карточки; её меняют ADR/spec, не «заодно в if».

**Объект вердикта.** PR в `period.py` / `victory/engine.py` / migrations DML / YAML; сиды vs SQL.

**Вопрос ревью.** Чтобы сменить это число или текст карточки, достаточно данных — или нужен программист править ветвление?

**Нарушение выглядит так.**
- Каталог событий одновременно в Python-сидах, SQL-миграциях и YAML (до [ADR-008](docs/decisions/ADR-008-events-catalog-single-source.md)).
- Победа захардкожена формулой 3× в коде при живом `victory_config_json` ([ADR-002](docs/decisions/ADR-002-victory-engine-and-template-config.md); legacy `evaluate_mvp_victory` только для старых тестов).
- Character XP/level как ось прогрессии событий ([ADR-003](docs/decisions/ADR-003-remove-character-progression.md)).
- Новые `INSERT` сюжетов в `backend/migrations/*event*.sql`.

**Покупаем.** Баланс и сюжет калибрует не только тот, кто пишет Python; diff контента читаем в git.

**Платим.** Нужны загрузчик, контракт YAML и дисциплина не «быстренько» поправить цифру в `if`.

**Порождает правила.** [ADR-008](docs/decisions/ADR-008-events-catalog-single-source.md); [`data/events/README.md`](data/events/README.md); skill `create-event` vs `game-economy-and-victory`; [`backend/migrations/README.md`](backend/migrations/README.md) (baseline = DDL, не DML контента); [ADR-002](docs/decisions/ADR-002-victory-engine-and-template-config.md).

**Соответствие.** Обязательно.

**Якорь.** `py -3 -m pytest tests/test_mvp11_yaml_catalog.py -q` (из `backend/`); гейт свода проверяет существование `data/events/mvp11/catalog.yaml` и этого теста. Линтер «нет новых INSERT событий в свежих миграциях» — не в этом скрипте (см. отклонения, держим skill db-baselines).

## Реестр осознанных отклонений

| Принцип | Где | Почему нельзя проверить / закрыть сейчас | До чего держим |
|---------|-----|------------------------------------------|----------------|
| C-Y | Молчание агента | Журнал видит только записанные разборы | Пока C-Y жив: не выдаём «100% разборов пойманы». Снятие: появятся обязательные session-записи — тогда пересмотреть якорь, не делать вид, что молчание ловится |
| C-Y | `.cursor/hooks.json` | Гейт свода **не** в blocking hook | Не раньше **2026-09-16** и не раньше, чем `check_conventions.py` отработает вхолостую ≥7 дней без ложных красных на main-потоке |
| C-1 | Поведение агента «аудит = spec» | Нет детектора намерения | Пока жив C-1: якорь только структурный (тексты иерархии). Снятие: не планируется автоматика намерения |
| C-3 | Источник ставки продукта | В каталоге нет поля `source` / `game_fiction` | **2026-12-01** или раньше: поле в шаблонах вкладов/долгов/страховок **или** явный отказ от (1) в формулировке C-3 |
| C-3 | Дисклеймер «не совет» в UI | В GDD-outline есть, в клиенте нет | **2026-12-01**: экран/футер с границей образования ≠ совет **или** перенос в «Целевое» с новой датой |
| C-4 | INSERT событий в SQL | Гейт свода не парсит все `migrations/` | Пока ADR-008 принят: проверка на ревью + skill `db-baselines-and-migrations`. Снятие: отдельный скрипт по `migrations/*.sql` |
| — | Детерминизм picker (`random.random` без seed) | Не принцип этого свода: нет живой нормы «один сид — один лог» в runtime | Не заводим C-* пока нет продукта «seed в логе». QA-аудит это фиксирует, это не канон |

Бессрочных отклонений без даты/условия нет: «пока принцип жив» — условие, не отмена.

## Не вошли (кандидаты, отвергнутые)

| Кандидат | Почему не принцип |
|----------|-------------------|
| Измеримая учебная цель у каждой механики | В репо нет реестра навыков; педагогика — «через прожитый месяц». Заводить реестр = выдумать норму |
| Детерминизм симуляции как обязательный runtime | Picker не сидирован; это долг QA, не выдержанный вердикт |
| Версионирование файла сейва | Прогресс — серверный `GameProfile` + SQL-миграции, не клиентский save format |
| Словарный линтер «термин без первого объяснения» | Граничит со стилем; есть [GLOSSARY](docs/foundation/GLOSSARY.md) как правило |
| Бюджет кадра/памяти числом | Числа нет; skill performance — deferred |
| Детский COPPA-контур | ЦА 30+ ([TARGET_PLAYER](docs/foundation/TARGET_PLAYER_AND_SESSION.md)); ужесточение «для детей» было бы вымыслом |

## Как менять этот файл

1. **Случай** — конкретный объект, на котором принцип дал неверный вердикт либо цена оказалась иной. Без случая пересмотр не начинают.
2. **Основание** — одно из трёх (C-X).
3. **Предложение** — новая формулировка целиком + что станет с уже сделанной работой.
4. **Согласование** — решение принимает человек; агент предлагает и обосновывает (C-Y).
5. **Пробный период**, если спорно: в поле «Соответствие» — `Пробное (до ГГГГ-ММ-ДД)` и критерий успеха словами. Просроченное «Пробное» ловит гейт.
6. **Запись** — строка в конце изменённой записи: что было, что стало, почему. Плюс строка в журнале `docs/conventions/reviews.yaml`.

Принцип перезаписывается на месте. Идентификаторы не переиспользуются. Нельзя ослаблять или удалять принцип ради зелёного гейта.

### Журнал разборов (C-Y)

Файл: [`docs/conventions/reviews.yaml`](docs/conventions/reviews.yaml). Исходы: `pending` / `accepted` / `partial` / `rejected` / `withdrawn`.

### Команда гейта

```
py -3 scripts/check_conventions.py
```

Не подключать в git-hook и не вшивать в `npm run check:guardrails`, пока команда не отработала вхолостую минимум неделю (см. отклонения).
