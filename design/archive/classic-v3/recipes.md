# Рецепты: от задачи к решению

Система отвечает на задачу, если пройти три вопроса: **что это в игре** (ход, деньги, рост, риск, нейтраль) → **это нажимается** (фишка с lift) **или нет** (клетка) → **какой компонент** уже это делает. Ниже — типовые задачи проекта.

## Новый экран или вкладка

- Поле `mq-board`, колонка `mq-column`, gutter `mq-space-4`. Шапка — `title` + фишка хода (Cell `now`) справа. Таббар — TabBar.
- Сверху — вывод, ниже — детали. Карточки-клетки через `mq-space-3`.
- Один фиолетовый акцент на экран. Всё остальное — клетки.
- Состояния loading / empty / error — из States, обязательно все три.

## Новое действие игрока

- Главное действие экрана — Button `primary` (одно). Второстепенные — `secondary` или BoardButton.
- Действие с деньгами, которое ещё не сделано и выгодно (зарплата) — ActionPieces `hot` (золото). Не делай золотыми опасные действия.
- Деструктивное (продать, закрыть, погасить) — подтверждение через `useMqxConfirm` (Sheet), текст называет последствие, кнопка названа действием («Продать», не «Удалить»). Кнопка `destructive` только для потери денег/прогресса.
- Пока сервер думает > 300 мс — спиннер в кнопке; до этого — только pressed. Денежные POST — идемпотентны, кнопка disabled на время запроса.

## Новое событие (карта)

- EventCard: полоса домена + вариант выбора с ImpactChips. Последствия — деньги, затем потребности.
- Обычное событие — край `mq-turn`. Узловое — край `mq-coin-rim`, судьбоносное — двойной край (`th-event--key`, `--fate`). Поля `beat` в YAML пока нет — это предложение аудита 2026-10-25 (L4); до него все карты обычные.
- Текст варианта — глагол + объект («Отремонтировать за свои»), не «Вариант А».
- Объяснение последствия (debrief) — строка `note` в ритуале, ≤140 символов: «что случилось → правило большого пальца». Поля `choices[].debrief` в схеме тоже ещё нет (аудит, L5).

## Показать сумму или изменение

- Сумма — `th-money` / `MoneyText`, без копеек. Крупная — `money`, в плитке — `cell-value`, в строке — `body-strong`.
- Изменение — ImpactChips: знак + стрелка + цвет. Плюс — `mq-gain`, обычный минус — нейтральный, потеря от риска — `mq-risk`.
- Анимировать изменение — count-up от старого значения; награда — монеты + `mq-ease-reward`.

## Конец хода: показать, что спишется

- ClosePreview под «Завершить ход»: «Спишется N ₽ · останется M ₽» из `period_close_preview`; зарплата, пока не забрана, в превью не входит.
- Минус — остаток красным; третий минус подряд — плашка `mq-risk-soft`. У подушки — «не платит расходы».
- Не вшивай сумму в кнопку и не открывай подтверждение на каждый ход: строка видна до нажатия, этого достаточно.

## Прогресс и цель

- Путь к цели — GoalTrack: точки шагов цели, финиш — золотая клетка с монетой. Не прогресс-бар процентов.
- Шкалы состояния (потребности) — NeedsBars: тонкая полоса `mq-r-pill`, цвет по зоне: норма `mq-gain`, низко `mq-warn`, критично `mq-risk` + слово.

## Капитал (имущество, вложения, долги, страховки)

- CapitalLot с тоном полосы. Строки: название слева, сумма справа, действие текстом под суммой.
- Закрытая механика — `locked`: пунктир и «Откроется на шаге …».
- Порядок разделов: Доходы → Расходы → Инвестиции → Страховки → Имущество → Обязательства.

## Подсказка, онбординг, Монетка

- MonetkaTip — одна строка в пузыре. Срочное — `data-tone="warn"`.
- Подсказка привлекает внимание двумя пульсами при появлении и замирает. Без бесконечной анимации.
- Длинные объяснения — в help-лист (`MqxEventHelpSheet`, `MqxNeedsHelpSheet`), не в подсказку.

## Модалка, лист, подтверждение

- Лист снизу (Sheet): `mq-cell-raised`, `mq-r-card` сверху, `mq-elev-3` над `mq-scrim`, вход `mq-dur-slow` enter. Список в листе — строки с тонким разделителем и действием-словом («Купить», «Взять»), без цветной полосы.
- `role="dialog"`, `aria-modal`, заголовок `title`, явная кнопка закрытия; действия внизу, главное — справа/широкое.

## Финал партии

- RunFinale: победа — золотая клетка с персонажем и кубком, «Играть дальше»; поражение — факт риска на `mq-risk-soft` + 2–3 совета + «Переиграть».

## Маркетинг, посты, лендинг

- Логотип G1/G2 из группы Logos, tagline «Финансы как игра». Монетка не перекрывает логотип.
- Цвета — те же роли. Градиент violet → indigo `#4338ca` допустим только в hero промо, не в UI.
- Голос в постах — 3-е лицо ведущего («Разработчики добавили…»), не «мы влили PR».

## Где проверить

- Живой каталог prod-компонентов — `#/dev/mqx` (только dev-сборка).
- Макеты до утверждения — `design-lab/` (`cd design-lab && npx serve .`).
- Перед merge UI — субагент `mqx-ui-reviewer`, чеклист экрана в `BRANDBOOK_MQX.md` §9a.
