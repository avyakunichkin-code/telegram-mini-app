не автоматически загружаемые правила. В корневом чате игровой навык при необходимости
открывается по явному пути из game/.agents/skills; копировать его в корневой каталог не нужно.

## Доставка

Idea: проблема, аудитория, scope, assumptions → существующие vision/ideas продукта.
Spec: контракт, состояния, CS happy/boundary/error/invariant и AC по риску.
Plan: согласованный срез, зависимости, команды проверки и откат. В длительной задаче
поддерживай progress, решения, результаты проверок и незакрытые вопросы в этом плане.
Implementation: исполни согласованный срез и проверь результат. Исправление понятного
бага или опечатки не требует цепочки новых артефактов.

Используй существующие roadmap/backlog/spec/plans своего продукта; общие изменения —
в корневом docs/plans. Не вводи параллельные PLANS/GOALS/PROMPTS без отдельной пользы.
ADR объясняет почему, spec — что, plan — как, handbook пересказывает текущий код/spec.
[Иерархия источников](../DOCUMENTATION_SYSTEM.md) сохраняется.

## Контракты, схема, проверка

Общие навыки api-contract-change/db-migration/review-change/verify-change выбирают
реальные файлы и runner по профилю продукта. Не переносить формат ошибок, DB startup,
дизайн или игровые гейты в соседнее приложение по сходству стека.
Изменение shared проверяется у реальных потребителей. Изменение fincore сохраняет
границы ADR-016 и требует предусмотренных golden/balance-проверок GAME.

Результат содержит cwd, executable, команды с exit code, проверенный сценарий,
пропуски и риски. Для AI — checker и behavioral tests. Для docs не нужны продуктовые
сборки, если поведение или конфигурация приложений не затронуты.

Release, реальная миграция, внешняя отправка и публикация требуют соответствующего
поручения; согласование локальной реализации само по себе их не разрешает.
