# Памятка владельца

Для работы над GAME открывай game/, над PLAN — plan/. Корневой проект предназначен
для shared и межпродуктовых задач. [Архитектура](CODEX-ARCHITECTURE.md) и
[маршрут](CODEX-PROCESSES.md) описывают области, а [COMMANDS](COMMANDS.md) — команды.

Семь навыков в корне общие; шесть в game/.agents/skills относятся к игре.
PLAN использует общий delivery/API/DB/review/verify-процесс и собственные docs.
В корневом чате игровой навык можно открыть по явному пути при задаче GAME.

Примеры GAME: исправь README; проверь зарплату; добавь YAML-событие; внедри
утверждённый MQX-вариант. Примеры PLAN: добавь поле отчёта вместе с потребителем;
проверь миграцию чекапа; исправь aria-label по текущему дизайну PLAN.
Общие навыки выбирают продукт по поручению и путям, не отправляют PLAN к игровой API.
Новый дизайн проходит человеческое утверждение по процессу своего продукта.

Для сложной работы поддерживается существующий план: scope, progress, решения,
команды/exit code и открытые вопросы. Новые GOALS/PLANS/PROMPTS не обязательны.
Роли вызываются только при необходимости и разрешении клиента; review не approval человека.

## Проверка контекста

В новом чате каждого проекта попроси перечислить активные инструкции и доступные
репозиторные навыки. Ожидаемые области: root — 7 общих; GAME — 7 + 6; PLAN — 7.
Глобальные и bundled skills сюда не включены. Метаданные навыков могут обновляться
автоматически; если обновление не появилось, открой новую сессию.
Модель цепочки предков проверяется tests, но не выдаётся за наблюдение клиента.

CLI/CI: node scripts/codex/check.mjs и node --test scripts/codex/*.test.mjs.
Отчёт текущего разделения — [SKILL-SCOPES](CODEX-SKILL-SCOPES.md).
Нативное исполнение hooks требует штатного trust и безопасного allow/deny smoke
по [runbook](CODEX-HOOKS.md); наличие конфигурации и зелёные subprocess tests
не доказывают активную блокировку. Глобальные разрешения не меняются.
