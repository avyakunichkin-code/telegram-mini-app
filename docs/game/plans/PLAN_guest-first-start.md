# Гостевой старт · план реализации

07.11.2026. Реализация по [спецификации](../specs/features/SPEC_guest-first-start.md). Направление одобрено, вариант А утверждён 07.11.2026: «Отлично, внедряй».

1. **Идентичность**: User.is_guest, GuestSession с хешем capability, индексами/expiry, baseline DDL + migration 0052. Версия обучения хранится в starter_params_json партии. Тесты: schema canon, повтор миграции, ownership.
2. **Сервис и контракт**: guest resume/create, атомарный claim, уникальность email, отзыв session, /me.is_guest. Старый login/register не менять семантически. Тесты доступа/конкуренции/сбоев.
3. **Frontend авторизация**: явно различить visitor/guest/member; guest resume после access expiry; не путать logout с потерей гостевой capability. Ошибки retry без дублей. Старые сохранения не перезаписывать.
4. **Утверждённый старт**: новый welcome с начать/продолжить/войти, автоматический Студент. MQX + каталог + native parity. Нет обязательного ввода имени партии.
5. **Quick-start curriculum**: новая версия для новых пользователей, раннее событие, короткие action-подсказки, необязательная подушка. Существующие beat ids/прогресс сохраняются. Доменный backend pytest и deterministic balance diff.
6. **Добровольное закрепление**: после первого итога, при отсутствии overlays; claim форма и отказ. Постоянная ссылка в меню. Существующий login явно переключает набор сохранений, не сливает данные.
7. **Проверка**: полный backend pytest, FE unit/build/guardrails, критичный guest→игра→claim→F5 и конфликт email, mobile/desktop. Утверждения и канон в одном срезе. Никакого деплоя/коммита/переноса реальных пользователей автоматически.

Откат: вернуть прежний публичный маршрут без удаления привязанных пользователей; существующий вход продолжает работать. Миграции только additive, гостевые данные не удаляются ради отката UI. Срок гостевой сессии — 180 дней, автоматический cleanup не включён.
