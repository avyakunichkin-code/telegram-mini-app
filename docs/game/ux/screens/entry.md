# Вход и первый гостевой ход · as-built

Источник поведения: App.jsx/PlayerEntry, GuestWelcomeScreen, AuthContext, guest_auth, game/guest-start. Спецификация: [guest-first-start](../../specs/features/SPEC_guest-first-start.md). Утверждение: [вариант А](../../../../design-lab/screen-refresh/guest-first-round/APPROVED.md). Статус внешнего выпуска — pending-balance.

| Состояние | UI / переход |
|---|---|
| Новый посетитель | G1, финансовые решения без риска для настоящих денег, «Начать играть», «Уже играл? Войти» |
| Подготовка | Кнопки блокируются, состояние загрузки, без обязательного имени/почты |
| Ошибка | Понятное сообщение и повтор; действующая гостевая сессия и первая партия переиспользуются |
| Первая партия | Автоматически Студент, сразу пульт, события с P1, помощь по запросу |
| Первый итог | Сначала итог; предложение аккаунта не перекрывает итог/события/финал |
| Создание аккаунта | Claim сохраняет того же пользователя/партию; занятая почта — конфликт, гостевой прогресс не удаляется |
| Отказ | Следующий ход доступен, ссылка регистрации остаётся в меню |
| Существующий аккаунт | Вход открывает его сохранения без слияния с гостем |
| Истёк access JWT | При живой cookie сессии восстановить доступ к той же партии |

Гостевой доступ зависит от браузерной сессии, аккаунт нужен для другого устройства. Не обещать сохранность доступа после очистки browser data. Web Locks сериализует первый запуск между вкладками в поддерживаемом браузере; fallback этой гарантии не даёт.

Монетка Б, карточки действий и спокойная помощь — [dashboard](dashboard.md). «Выбор жизни» — [character-pick](character-pick.md) для следующих новых игр; он не обязательный шаг первой гостевой сессии.
