# Каталог событий: разнообразие и отбор

scope: all (структура, баланс-контракт и lifecycle); ранний случайный пул P3–P12.
catalog: mvp11; analyst: agent; verdict: **CONCERNS**.
Реальные анкеты/партии не использовались. YAML и игровые данные не менялись.

## Главный результат

Недостаток разнообразия нельзя объяснять только числом историй. Каталог
содержит 76 определений, 72 активны. Найден воспроизводимый дефект отбора:
экспоненциальные ключи `-ln(U)/weight` сортировались по убыванию. Для таких
ключей выигрывает **минимум**; прежняя сортировка предпочитала малый вес.
Таким образом, fatigue, понижающий вес после выбора, повышал фактический шанс
повтора, а needs rescue multiplier уменьшал шанс подходящего события.

Это не новое продуктовое решение о весах, а несоответствие отбора уже
реализованным fatigue/rescue-правилам. Аудит завершён без правок YAML;
исправление передано в отдельный инженерный срез:
[отчёт исправления](../../ops/EVENT_WEIGHT_SELECTION_2026-11-05.md).

## Доказательство дефекта выбора

20 000 независимых выборов, `random.seed(20261105)`, один слот, два кандидата.
Это тест реальной `_weighted_sample_without_replacement`, не живая частота.

| Условие | До | После |
|---|---:|---:|
| Вес1000 против1: выбран1000 | 20 (0.10%) | 19 980 (99.90%) |
| Одинаковый базовый100: выбран свежий против4выборов | 5 033 (25.17%) | 14 967 (74.84%) |
| Одинаковый базовый100: выбран rescue×10 | 1 878 (9.39%) | 18 122 (90.61%) |

В изолированном Student-пуле P3–P12 на100seed (0…99), по20показов:
среднее уникальных **12.70 → 16.21**, повторных показов **7.30 → 3.79**,
максимум одной карточки **4 → 3**. Использованы actual domain rotation,
tier/eligibility/cooldown и счётчики; все показанные карты считаются выбранными.
Контекст без активов/долгов фиксирован, needs rescue/приоритеты/цепочки и
финансовые последствия не моделировались. Это сравнение только отбора,
не полный balance playtest и не обещание для реального игрока.
