# Калибровка событий после исправления веса

Владелец: «Продолжай» после предложения сохранить правильный отбор и отдельно
калибровать события. Это не принятие новых baseline и не снижение целей.
Primary event-authoring + balance-playtest. Сначала shadow experiment,
затем только подтверждённый срез в YAML.

## Бюджетный отдых в family_vacation_offer

Существующая цепочка предлагает отпуск по кредитке сейчас, накопить и поехать
позже или отказаться. Для профиля с низким здоровьем и ограниченным бюджетом
нет короткого семейного отдыха без будущего кредита.

Добавить четвёртый выбор «Короткий отдых рядом с домом»:

- cash_pct_salary0.12 (при зарплате200 000 ₽ —24 000 ₽;
  actual salary берётся из партии). Audience остаётся Manager/Entrepreneur;
  Student/Professional этим выбором не охватываются.
- needs_delta: health+15, social+12, comfort−2.
- Нет enqueue_event/долга/регулярного расхода. Отдых происходит сейчас;
  полная цена списывается сразу, без эпилога и скрытого платежа.
- Description: «Несколько дней рядом с домом: сменить обстановку и побыть
  с семьёй. Оплата сразу, без кредитной карты и платежей в следующих ходах».

Trade-off: по сравнению с кредитной веткой healthвыше, socialниже; платишь
сразу вместо будущего долга. По сравнению с отказом — явная цена. Никакой
ветке не присваивается бесплатное улучшение. health15≤axis cap15; сумма
положительных27 и net25 укладываются в price-curve corridor при12%salary.
Семейный отдых: health+social основные, comfortвторичная отрицательная.

Наследуются domain social_family, content_class/event_slot/audience/tier2
и lifecycle родительского события: max_per_profile2/cooldown12. Не добавляем
отдельный definition, потому что это новый выбор той же развилки, не новый
профильный вариант. Существующие branches/context/follow-up не меняются.
Impacts до нажатия: разовое списание12%salary, здоровье+15, связи+12,
комфорт−2; нет будущего начисления/кредита/бесплатного бонуса.

## Проверки и границы

Стартовые деньги/зарплаты, victory thresholds, износ нужд, ставки, число слотов
и правильная сортировка весов не меняются. Нет новой схемы/SQL/API/layout.
Shadow40p entrepreneur seed42, затем7/99; восстановить winwindowP12–P30
без поражения. После YAML — каталожный контракт/Pareto/price curve,
предпросмотр impacts, новые выборы и seeds idempotency, полный backend pytest,
весь11×40manifest и отдельный multi-seed риск. Baselines без человека не менять.
