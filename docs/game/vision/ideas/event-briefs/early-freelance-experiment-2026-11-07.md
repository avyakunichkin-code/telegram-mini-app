# Эксперимент: подработка Студента на пятом ходу

Расчёт завершён: 12 партий, метрики и решение [ресурс](../../../../balance/reports/early-freelance-2026-11-07/SUMMARY.md).
Итог CONCERNS; production-каталог и baseline остаются прежними.

Владелец 07.11 согласовал пробу ранней цепочки после обсуждения рутины с
5–7-го хода: «Согласен, давай попробуем». Разрешён изолированный эксперимент;
это не утверждение нового production-каталога, ставки, награды или baseline.

## Гипотеза и варианты

Студент уже освоил цикл, но обычный пул до P10 ограничен tier1. Существующий
сюжет Миши tier2 может дать выбор на несколько ходов раньше, сохранив
систематическое накопление. Гипотеза удовольствия проверяется человеком;
симуляция измеряет экспозицию, экономику и поведение конкретных бот-политик.

- A: текущий Student, onboarding v2, неизменённый каталог.
- B: тот же каталог; mq11_freelance_project_offer гарантированно занимает
  один обычный слот на P5, если он есть в eligible candidates. Второй слот
  остаётся случайным. На P5 только этому offer временно назначается tier1;
  с P6 возвращается tier2. Другие tier и eligibility не меняются.

Гарантированный показ выбран для проверки воздействия сюжета, а не частоты
его случайного появления. Это сильнее простого расширения пула: по результату
нельзя заключить, что одно понижение tier даст тот же эффект.

## Контент и trade-off

Используется [существующая цепочка](../../../../../data/events/mvp11/chains/freelance_project.yaml),
новые definition_key и YAML не создаются. Persona: только Студент; profile,
period_choice, once_per_profile, cooldown12. Отказ остаётся допустимым выбором.
Первый выбор: аванс8000 сейчас / 22000 после защиты / отказ с эффектами needs.
На N+2 работа или отдых; N+4 сдача; N+5 выплата. Стоимость needs, качество,
авансовые удержания и премия из существующего контента не меняются. Подробные
effects, lifecycle продолжений и условные preview сохраняются без переписывания.
Остальные сюжетные цепочки, зарплата, расходы и победа не изменяются.

## Реализация и изоляция

[CLI](../../../../../backend/scripts/experiment_early_freelance.py) использует
существующий balance_simulate и временную SQLite. Process-local mock-контекст
перехватывает scheduler/selector только на время одного run; затем функции
восстанавливаются. Изменения EventDefinition существуют только в временной БД.
Скрипт не предназначен для запуска внутри сервера и не открывает вариант B
через браузерный URL. Основной каталог/production/сохранения не затрагиваются.

Обе группы используют policy, seed, template, onboarding и горизонт одинаково.
Одинаковый seed не означает одинаковую последовательность остальных событий:
замена слота меняет расход RNG и дальнейшую траекторию. Сравнение показывает
эффект всего варианта B, не чистую прибавку гонорара при фиксированном остальном.

## План проверки

Student, chain_runner и needs_keeper, seed7/42/99, 40p: 12партий.
Сохранить полные JSON обеих групп и diff к текущему контролю; отдельно сравнить
seed42 с принятыми legacy baseline, отметив onboarding mismatch и исходный drift.
Исходные baseline не перезаписывать. Отчёт содержит win/goals/defeat,
cashP12/P20/P40, events_resolved и выбранные ветви freelance. Экономические флаги
не отменять успешным exit CLI. Отказ бота от подработки также результат.

Проверки изоляции: B показывает offer наP5 не добавляя третий обычный слот;
выбранные продолжения приходят по существующему расписанию; следующий A
не наследует ранний tier; mock-функции восстановлены после run.

Выход для человека после технической проверки: безопасный способ попробовать
вариант на отдельном стенде потребует отдельного среза; текущий localhost
не объявляется изменённым этим CLI. Критерий наблюдения — пришлось ли
планировать несколько ходов, изменилось ли решение из-за состояния needs/cash,
появилось ли желание увидеть последствие; не только скорость победы.
