## Запуск на синтетическом снимке

Из корня репозитория, Node 22+, без зависимостей:

```powershell
node scripts/playtest-report.mjs docs/ops/fixtures/playtest-synthetic.json 2026-11-01T00:00:00Z 2026-11-02T00:00:00Z 2026-11-07T00:00:00Z
node --test scripts/playtest-report.test.mjs
```

Первый запуск печатает агрегированный JSON в stdout. Скрипт не подключается
к БД/сети, не читает env и ничего не записывает. Вход передаётся явно; fixture
содержит только вымышленные идентификаторы. Production-экспорт в этот срез
не входит, реальные анкеты агент не читает. Персональные поля отвергаются
whitelist-валидацией. Это минимизация полей, не обещание анонимности.

## Контракт снимка v1

Все пять верхних полей обязательны. Неизвестные поля отклоняются.

| Массив/поле | Поля строки |
|---|---|
| build_revision | git hash 7–40 hex; метка билда волны, не доказательство версии каждой партии |
| accounts | id, guidance_completed (boolean) |
| profiles | id, user_id, save_kind, created_at, run_outcome (null/victory/defeat) |
| closings | game_profile_id, period_index, closed_at |
| surveys | user_id, survey_key=first_turns_v2, submitted_at, game_profile_id (nullable) |

Даты ISO с timezone. Все записи должны отражать состояние observedAt,
будущие записи отклоняются. Нельзя пометить текущий снимок прошлой датой:
run_outcome/guidance не имеют достаточной истории для исторического пересчёта.
Указывать реальное время получения снимка. Партии вне окна исключаются;
закрытия после конца окна учитываются до observedAt — это наблюдение когорты,
не счётчик операций внутри окна. Возраст самой молодой партии виден в отчёте.

Повтор одной записи закрытия считается один раз по profile/period. Дубликаты
партии, аккаунта или анкеты аккаунт/версия — ошибка, не дополнительная конверсия.
Изменение статуса гостя не создаёт новую партию. Старые Plan строки можно
представить для контроля исключения; это не поддержка режима Plan.

Опрос имеет game_profile_id в текущей модели: явную корректную связь сохраняем.
Ответ без связи или с другой партией того же аккаунта не приписываем партии
когорты. Содержимое ответов и свободный текст в снимок не включаются.

## Человеческая часть

Готовый [сценарий ведущего, задания и рубрика](../foundation/PRE_ALPHA_OBSERVATION_2026-11-07.md).

Технический отчёт не измеряет понимание. Для одной волны одного билда отдельно
записать агрегаты: число наблюдавшихся участников, самостоятельно закрывших
первый ход, правильно объяснивших счёт/подушку/капитализацию, получивших помощь
и случаев «не наблюдалось». Предлагаемый критерий 8/10 принят; неполные
наблюдения показывать явно, не засчитывать отсутствующий ответ как успех.
Случаи без подходящего примера разбирать отдельно, не скрывая их в знаменателе.

Ни fixture, ни зелёные тесты не означают проведения волны или достижения 8/10.
Изменения UI, API, баланса, отправка приглашений и публикация не выполняются.
