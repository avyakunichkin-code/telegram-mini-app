# Пять улучшений игрового опыта

Направление принято владельцем в чате 07.11.2026: «Согласен, давай сделаем это»
в ответ на пять предложений: темп победы, объяснение результата, последствия
событий, адаптивное обучение, измерение прохождения. Это разрешение готовить
срезы, не утверждение ещё не выбранных порогов или макетов. Этот документ —
конкретный проект следующей итерации для рассмотрения, не новый канон экономики.

## Сверка с текущей реализацией

| Темп победы | Калибровка A; draft двух актов | Проверить A на людях; выбрать параметры продолжения по результатам |

| Последствия событий | Контекст, цепочки, preview future_payments B | Проверить различимость альтернатив и завершённость трёх сюжетов |

## Цель и критерии

Игрок самостоятельно закрывает ход, объясняет изменение денег и выбирает
следующее действие; между обучением и финалом остаются содержательные решения.
Проверка — наблюдение и ответы людей вместе с серверной историей.
Результаты ботов не называются результатами человеческого плейтеста.

Для первой волны предлагаем: минимум 8 из 10 участников самостоятельно
закрывают первый ход; минимум 8 из 10 правильно различают счёт, подушку и
капитализацию на конкретном примере. Это предлагаемые критерии, не измеренные
значения и не ранее принятые release gates. В отчёте приводить числитель,
знаменатель, помощь ведущего и пропуски; при другом размере группы — доли
вместе с абсолютными числами, без заявлений о статистической значимости.

## Срез 1: измеримое прохождение текущей A

Определения и критерии среза 1 согласованы владельцем 07.11.2026: «Хорошо,
продолжай». Реализация офлайн-отчёта и контракт минимального снимка:
[runbook](../../ops/PLAYTEST_REPORT.md). Остальные срезы остаются draft.

Первый срез не меняет экономику, UI или публичный API. Выход — протокол и
таблица агрегированных результатов на синтетических fixtures и затем на
разрешённой волне. Реальные ответы/анкеты в репозиторий не сохраняются.

### Определения воронки

Единица основного анализа — партия Game. Отдельно считать людей/аккаунты,
не складывать эти числа. Когорта — партии, начатые в заданном полуоткрытом
окне UTC [from, to); возраст наблюдения указывать в отчёте. Гость, сохранивший
ту же партию в аккаунт, не создаёт второй старт.

| Этап | Источник/условие | Ограничение |
|---|---|---|
| Старт | Серверное создание GameProfile | Открытие лендинга не считается стартом |
| Первый ход | Хотя бы одна PeriodEconomyClosing этой партии | period_index не заменяет запись закрытия |
| Пять ходов | Не менее пяти закрытий этой партии | То же определение, что приглашение в опрос |
| Финал | Зафиксированный outcome партии | Не считать dismiss финала новой победой |
| Опрос | Ответ first_turns_v2 | Ответ связан с аккаунтом, не автоматически с каждой его партией |

Завершение O3 хранится на User. Поэтому выводить его отдельно как статус
аккаунта, не как достоверное событие завершения обучения данной партии.
Неприсоединимый ответ опроса остаётся в отдельном агрегате, без предположения
«последняя партия = партия ответа». Пропуск опроса не означает недовольство.

Неактивность не доказывает отказ от игры: сообщать «последнее наблюдение»,
не «бросил из-за сложности». Активное время не выводить из разности дат
старта/финиша. Пока нет достоверной маркировки версии контента и баланса,
сравнение вариантов не проводить; использовать изолированную волну одного
билда и фиксировать git revision вне пользовательских данных.

### Сценарий наблюдения

1. Новый участник начинает с текущего старта без подсказок ведущего.
2. После первого итога объясняет, что изменилось на счёте и почему.
3. На доступном примере различает перевод, расход и капитализацию; если
   подходящего примера не было, пометить «не наблюдалось».
4. После обучения называет следующую цель и выбирает действие.
5. По желанию проходит встроенный опрос; отдельная заметка ведущего содержит
   только агрегируемую категорию затруднения, без контактов и личных финансов.

Категории: старт / навигация / зарплата / счёт-подушка / итог / инвестиции /
потребности / события / цель / техническая ошибка / другое. Сначала записать
наблюдение, затем гипотезу причины. Искусственный тест не заменяет участника.

## Срез 2: объяснения и обучение

Сначала воспроизвести ошибки понимания на текущем compact A и O3. Для каждой
подсказки проверить источник суммы: текущий overview/blueprint либо явно
помеченный пример. Отсутствующее значение не заменять нулём или суммой Студента.

Предлагаемое поведение: освоенное действие не требует повторного учебного
шага; доступно повторное объяснение; подсказка не выполняет финансовую операцию.
Конкретные gates, сохранение прогресса и доступность по ролям уточняются в
существующей [O3 spec](SPEC_onboarding-o3.md). Существующие beat id не менять
без миграции; User guidance не смешивать с profile onboarding.

Новое раскрытие причин итога проектировать только если имеющиеся подробности
не отвечают на наблюдаемое затруднение. Суммы берутся с сервера; проценты во
вклад не выдаются за поступление на счёт. Прогноз не называется фактом.
Layout/CTA/sheet: lab → явное утверждение → MQX/prod/canon.

## Срез 3: три законченных сюжета

На базе существующих семейной, автомобильной и freelance цепочек подготовить
три event brief, а не добавлять повторяющиеся карточки. Для каждого: разрешённые
роли, prerequisites, исходное решение, все ветви, ближайшие и отложенные эффекты,
завершение и условия недоступности продолжения. Студенту не навязывать
запрещённые blueprint автомобиль/кредит/страховку.

Сначала проверить текущие цепочки; новый контент только при подтверждённом
пробеле. Preview остаётся условным: альтернативы не суммируются, неизвестный
эффект явно неполный. Контент — YAML, не SQL. Изменение частоты/денег требует
balance diff и отдельного принятия результата; baseline не обновлять автоматически.

## Срез 4: содержательный финал

Продолжить существующую SPEC_victory-acts, не заводить третью модель победы.
Сохраняется решение 03.11: сначала волна на A, затем реализация двух актов.
До реализации выбрать для каждой роли цель пассивного дохода, знаменатель
расходов и состав учитываемого дохода; капитализация и деньги на счёт различаются.
Новые значения не выводить автоматически из старых диапазонов периодов.

Проверить политики на нескольких seed, время и решения людей. Для окна до
65 ходов необходим соответствующий горизонт; 40p его не доказывает. Уже
известный непринятый balance diff — открытый риск, не основание переписать эталон.

## Контракт и проверки

Этот документ не вводит endpoint, SQL или поле DTO. Если для воронки не хватает
данных, следующим артефактом будет additive API spec с require_admin_user,
403-тестом, знаменателями и пагинацией/границами периода; не расширять API попутно.

| Сценарий | Ожидаемый результат |
|---|---|
| Гость сохраняет аккаунт | Одна партия и один старт |
| Повтор ответа / повтор запроса закрытия | Ни нового ответа той же версии, ни второго закрытия |
| Две партии одного пользователя | Две партии; User guidance не считается двумя завершениями обучения |
| Неполная волна / нет ответа | Пропуски и срок наблюдения видны, причина ухода не придумана |
| Пропущенная сумма / неподдержанный preview | Честный fallback, без вымышленных денег |
| Перевод во вклад / капитализация | Не записываются как потребление / cash-поступление |

В реализации: backend pytest при логике/данных, FE unit/build/guardrails при UI,
critical-path Playwright при изменении взаимодействий, balance-playtest при
существенном изменении контента/экономики. Документ проверяется на ссылки и diff.

## Порядок и решения для утверждения

1. Утвердить определения среза 1 и предлагаемые критерии понимания; затем
   подготовить недостающий read-only отчёт на синтетических данных.
2. Готовность волны — существующий readiness process; приглашения и публикация
   не запускаются автоматически. Проведение людьми не отмечается выполненным агентом.
3. По наблюдениям выбрать точечные изменения обучения/итогов и event brief.
4. После волны выбрать параметры двух актов в существующей spec.

Главный выбор сейчас: согласовать предложенные определения воронки и критерии
понимания. Порог пассивного дохода и новые макеты в это согласование не входят.
