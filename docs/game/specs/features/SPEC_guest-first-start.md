# Гостевой старт и короткий первый игровой опыт

Направление подтверждено владельцем в чате: «Да, предлагаю реализовать рекомендации». Этот документ конкретизирует контракт перед новой продуктовой реализацией; вариант А с компактным заголовком утверждён 07.11.2026 сообщением «Отлично, внедряй». Источники текущего поведения: App.jsx, AuthContext, routers/auth.py, models.User, guidance/curriculum.py. Каналы PWA/web primary, одна экономика Game, без Plan/save_kind=plan.

## Результат

Новый посетитель начинает настоящую партию без почты/пароля. Партия, деньги, события и обучение сохраняются на сервере. После первого закрытого месяца можно добровольно привязать аккаунт. Регистрация не сбрасывает игру. Игрок со старым аккаунтом может войти отдельно.

## Пользовательский путь

1. Новый корневой маршрут: логотип G1, обещание «Твои решения. Твой финансовый опыт.», «Начать играть», ссылка «Уже играл? Войти». Не открывать автоматически форму регистрации.
2. Нажатие создаёт/возобновляет анонимную идентичность и автоматически начинает Студента, если у гостя ещё нет партии. Не запрашивать имя сохранения, роль, анкету или согласие на обучение. Ошибка/повторный клик не должны создавать дубликаты.
3. Первый ход нового curriculum: получить зарплату → принять решение в доступном событии → завершить ход. Подушка доступна, но не обязательная проверка. Короткая подсказка показывает одну ближайшую задачу; подробная помощь по запросу.
4. После первого настоящего итога: немодальное предложение «Твоя история уже началась. Закрепи её за аккаунтом» с действиями «Создать аккаунт» / «Продолжить без регистрации». Не показывать поверх итогов, события, финала или открытого финансового окна.
5. Отказ закрывает предложение на текущую сессию; постоянное действие остаётся в меню. Нельзя закрывать доступ к следующим ходам регистрацией.
6. Возврат в этом браузере: «Продолжить · ход N». Честное пояснение: без привязки прогресс доступен в этом браузере; очистка данных/истечение гостевого доступа может потребовать нового старта. Не обещать безусловное восстановление.

## Идентичность и данные

- Гость — отдельный серверный User с явным признаком is_guest, без выдуманного email и без известного игроку/другим пользователям пароля. Все существующие private endpoints продолжают проверять владельца.
- Для возобновления не полагаться только на текущий короткоживущий JWT. Отдельная гостевая сессия: криптографически случайный секрет в HttpOnly/SameSite cookie, в БД только хеш, конечный срок действия и отзыв. Для локального HTTP Secure отключён только в dev; production Secure обязателен. Браузерный frontend не читает секрет сессии.
- Повторный старт при действующей cookie возвращает того же гостя; создание партии идемпотентно и проверяется сервером. Публичный endpoint не принимает user_id, денежные остатки или профиль для присвоения.
- Новая регистрация превращает этого гостя в постоянного пользователя в одной транзакции. User.id и все FK/профили/история/прогресс сохраняются; выдаётся новая авторизация, гостевая сессия отзывается.
- Если почта занята: 409, партия и гостевая сессия остаются. Предложить войти в существующий аккаунт либо продолжить гостем.
- Вход в существующий аккаунт не переносит и не удаляет гостевую партию автоматически. До переключения ясно написать: «Откроются сохранения этого аккаунта. Гостевая партия останется в этом браузере». Доступ к гостевому возобновлению сохраняется до привязки/истечения сессии. Автоматическое слияние двух аккаунтов вне первого среза: требует самостоятельного перечисления всех ownership FK и правил объединения guidance/achievements.
- Существующие аккаунты, партии, административные роли и серверные права не изменяются. Anonymous не получает административных полномочий.

## Предлагаемые API

| Endpoint | Auth | Успех | Ошибки/инварианты |
|---|---|---|---|
| POST /api/auth/guest | гостевая cookie или создание | 200 Token + is_guest; установить/возобновить сессию | 429 при лимите; не принимать ownership от клиента |
| POST /api/auth/guest?resume_only=true | действующая гостевая cookie | 200 Token для того же гостя | 401 при отсутствии/истечении, не создавать пользователя |
| POST /api/game/guest-start | текущий guest bearer | 200 GameStartResponse: продолжить или атомарно создать Студента | 401 без bearer, 403 для постоянного аккаунта; обычный /game/start сохраняет смысл новой партии |
| POST /api/auth/guest/claim | текущий guest bearer + гостевая cookie | 200 Token, тот же user_id, is_guest=false | 401 без подтверждения сессии, 403 для чужой/не гостевой идентичности, 409 занятый email, 422 невалидный payload |
| GET /api/user/me | существующий bearer | прежние поля + is_guest:boolean=false | совместимое аддитивное поле |
| POST /api/login | как сейчас | существующий аккаунт | без скрытого переноса/удаления гостевых данных |

Claim payload использует те же ограничения email/password/password_confirm, что UserRegister. Ошибки русифицирует существующий frontend mapper. Пароли/токены не пишутся в отчёты, URL и screenshot. Миграция 0052 добавляет User.is_guest и GuestSession с индексами по хешу и владельцу; версия обучения использует существующий starter_params_json партии. Baseline только DDL, инкремент идемпотентен. Продакшн миграция и деплой отдельно не авторизованы.

## Обучение и события

Старые профили продолжают O3 без сброса. Новая версия обучения выбирается явно при создании нового гостя/пользователя. Не удалять старые beat ids и не выдавать старый прогресс за завершённый новым сценарием.

Для quick-start: первые два read-gate не обязательны; зарплата остаётся ручным действием. События показывают реальные эффекты текущего каталога на первом ходу, без подставной награды/искусственной победы. Число событий, выбор пула и порядок закрытия используют один движок; новый канал не создаёт другую экономику. Время открытия меняется только для новой версии старта. Before/after симуляция нужна, поскольку ранние события могут менять баланс. Если калибровка не подтверждает сценарий, не выпускать его как готовый.

## Критичные сценарии приёмки

- Первый клик → гостевая партия → действие без почты и пароля; ошибка старта даёт retry, не второй профиль.
- F5/закрытие вкладки/истечение access JWT при живой гостевой сессии → та же партия и остатки.
- Claim после нескольких ходов сохраняет user_id, profile_id, деньги, события, историю, цели и обучение; повтор не присваивает чужое.
- Совпавшая почта/сбой сети/конкурентные claim → ни потери партии, ни половинчатой привязки.
- Два гостя не читают/активируют/claim-ят профили друг друга; старый аккаунт не получает чужой прогресс.
- Отказ от регистрации позволяет следующий ход; предложение не возвращается на каждом экране.
- Старый пользователь проходит прежнее обучение и входит как раньше.
- Первый event/зарплата/подушка/закрытие работают на mobile 320/390 и desktop; один main, доступные формы, touch44, reduced motion.

## Проверки и выпуск

Backend полный pytest включая fincore; schema canon и guest/auth негативные тесты. PostgreSQL migrate/repeat на изолированном стенде при его наличии; SQLite не заменяет этот результат. FE unit/build/guardrails, Playwright guest→claim→resume и existing-login boundary. Guidance backend/frontend sync. Детерминированный баланс для изменившегося раннего окна, без автоматического baseline update.

Метрики как критерии исследования: старт → первое действие → первое решение → закрытие первого месяца → второй ход; предложение аккаунта/принятие/отказ отдельно. Не обещать рост конверсии до измерения. Длительность первой сессии — гипотеза, не новый period gate.

## Реализационные уточнения 07.11.2026

Гостевая сессия действует 180 дней, capability хранится HttpOnly-cookie; хеш на сервере, Secure + SameSite=None для HTTPS API с отдельным origin (локально Lax). Требуются разрешённый credentialed CORS и поддержка cookie браузером; предпочтителен same-origin API proxy. Автоудаление гостевых партий не включено. Создание ограничено 20 идентичностями в минуту на IP в процессе; повтор существующей сессии не расходует лимит.

Новый quick-start использует краткие необязательные подсказки о ближайшем действии вместо обязательного чтения; версия закреплена в starter_params_json партии. Количество событий за ход не меняется (2), порог доступности для версии 2 — ход 1. Старая версия — ход 3. Упрощение не подменяет экономику деморежимом.
