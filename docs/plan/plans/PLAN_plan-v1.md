Реальные пользователи — только после юриста ([ADR-017](../../decisions/ADR-017-plan-p2-without-game-gate.md) п.2).

Сверка 2026-11-03: этот план остаётся DRAFT; P3-01 — принятое решение, остальные срезы не объявлены реализованными. Вопросы для закрытия P2 и приоритизации P3 — [QUESTIONS](../QUESTIONS.md). Уточнение 2026-11-03: P3 после P2, исследование понятности параллельно. Рекомендуемые первые срезы — P3-02 и необходимая часть P3-09. Весь план остаётся DRAFT. [Решения](../QUESTIONS.md) · [План базы](PLAN_plan-foundation.md).

## Порядок и зависимости

### Очередь владельца · 2026-11-05

1. **P3-02** — 1–3 действия, отметки, сохранение и завершение шага. [Компактный B](../../../design-lab/plan-checkup/actions-round/index.html) явно утверждён владельцем 2026-11-05. API и UI реализованы в отдельном контуре Plan; результаты проверки — [отчёт среза](../audits/2026-11-05-step-actions.md).
2. **P3-09** — события выполнения действий и время чекапа; без финансовых сумм в payload. Реализовано 2026-11-05: серверные длительности, строгий контракт props и удаление событий; [результаты](../audits/2026-11-05-product-events.md).
3. **P3-08** — реализовано 2026-11-06: владелец явно утвердил вариант 2 «Журнал с полями». [Lab и canon](../../../design-lab/plan-checkup/history-round/index.html), [результаты внедрения](../audits/2026-11-06-history.md). История, открытие старых отчётов и сравнение двух завершённых чекапов читают сохранённые снимки, без пересчёта. P3-07 не входит автоматически.
4. **P3-12** — реализовано 2026-11-05: последний итоговый отчёт офлайн, месяц данных и время копии, очистка приватного снимка при выходе, смене сессии, 401 и удалении аккаунта. [Проверки и ограничения](../audits/2026-11-05-offline-report.md).

## Решения, которые принимает PO по ходу P3

- ~~P3-01: общий `journey` или свой движок~~ — свой (PO, 2026-11-02).
- P3-02, P3-09: описанные сценарии действий и события утверждены PO 2026-11-03; локальная реализация и проверки — 2026-11-05. Остальные срезы не объявляются завершёнными.

- P3-05: тексты 8–10 и согласия — через юриста; выпадает ли раздел инвестиций.
- Отступление P2: разделы чекапа хранятся JSON-документом (`checkups.data_json`), а не нормализованными таблицами spec. Нормализация нужна, если отчёт P3-10 потребует SQL по строкам разделов, — решаем в P3-10.
