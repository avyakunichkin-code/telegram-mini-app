# План деплоя «ТВОЙ ПЛАН» (SPL-406)

**Это план, а не выкатка.** Деплой Plan решает владелец продукта отдельно, и только после юриста по ПДн ([ADR-017](../../decisions/ADR-017-plan-p2-without-game-gate.md) п.2–3). До этого Plan живёт только локально и в CI на синтетических данных.

Роадмап — [`../ROADMAP.md`](../ROADMAP.md) (P2). Каркас, который выкатываем: SPL-402 (`apps/plan-api` на `packages/platform`), SPL-403 (`@tvoy/api-client`), SPL-405 (CI).

## Gates до первой выкатки

| # | Gate | Кто | Блокирует |
|---|------|-----|-----------|
| G1 | Юрист: согласие на обработку ПДн, политика, данные членов семьи от третьего лица, тексты правил 8–10, уведомление Роскомнадзора (spec open question 4) | PO + юрист | любых реальных пользователей |
| G2 | Почтовый провайдер в РФ для кода входа — новая зависимость, «ask first» в spec (open question 1) | PO | вход реальных людей (сейчас код пишется в лог) |
| G3 | Хостинг в РФ выбран, договор на обработку ПДн (поручение оператора) | PO | деплой |
| G4 | SPL-404 lab утверждён и перенесён в `apps/plan-web` | PO («утверждаем») | публичный домен |
| G5 | Явное «да» PO на выкатку | PO | деплой |

## Схема

```text
   plan.<домен>  (статика plan-web, CDN/объектное хранилище в РФ)
        │  /api  →  api.plan.<домен>
        ▼
   контейнер plan-api (uvicorn, 1–2 инстанса)  ──►  PostgreSQL `plan` (управляемый, РФ)
        │                                              ▲
        └── cron: purge раз в сутки ───────────────────┘
   почта: провайдер в РФ (G2)

   игра — без изменений: backend (game-api) и frontend-react на своих доменах и своей БД
```

Два приложения — два контейнера, два домена, две БД, два секрета ([ADR-016](../../decisions/ADR-016-two-products-shared-fincore.md) п.2, п.5). Plan не ходит в БД игры и не принимает её токены (CS-7).

## Окружение plan-api

| Переменная | Значение | Заметки |
|------------|----------|---------|
| `PLAN_ENV` | `production` | Строгий режим: без секрета старт падает; нет `dev_code` и `/api/dev/*`; миграции при старте не применяются |
| `PLAN_SECRET_KEY` | ≥ 32 байт, генерируется на хостинге | **Не равен** `SECRET_KEY` игры; ротация — новый ключ + перелогин всех |
| `PLAN_TRUSTED_PROXIES` | число своих прокси перед API, `0` если их нет | Обязателен: без него production не стартует. Иначе лимиты по IP станут общими на всех пользователей |
| `PLAN_DATABASE_URL` | `postgresql://…` управляемой БД `plan` | `postgres://` нормализуется на psycopg 3 (`tvoy_platform.db`) |
| `PLAN_CORS_ORIGINS` | `https://plan.<домен>` | Только домен plan-web |
| почтовый провайдер | ключи провайдера (G2) | Появятся вместе с мейлером вместо `LogMailer` |

## Порядок выкатки

1. Создать БД `plan` и пользователя с правами только на неё.
2. Собрать образ plan-api: `apps/plan-api` + `packages/fincore` + `packages/platform` (контекст сборки — корень репо, `pip install -r apps/plan-api/requirements.txt`).
3. **Миграции отдельным шагом:** `python -m plan_api.migrate` (job перед стартом релиза). Старт API схему не создаёт.
4. Старт: `uvicorn plan_api.main:create_app --factory --host 0.0.0.0 --port $PORT`. Health — `GET /api/health` (200 / 503 при мёртвой БД).
5. Cron раз в сутки: `python -m plan_api.purge` — уничтожение данных удалённых аккаунтов (spec: ≤ 30 дней).
6. Статика plan-web: `npm ci && npm run build` в `apps/plan-web`, `/api` — на `api.plan.<домен>` (прокси или `baseUrl` клиента).
7. Smoke (ниже) на обоих приложениях: Plan выкатили — игра работает как раньше.

## Бэкапы и данные

- Ежедневный снапшот БД `plan`, хранение ≤ 28 дней (purge раз в сутки + бэкап укладываются в 30) — тогда удалённый аккаунт исчезает и из бэкапов в срок 152-ФЗ (согласовать с юристом, G1).
- Логи без сумм вместе с `user_id`/e-mail; e-mail маскируется (`plan_api.mailer.mask_email`). Код входа в лог в production **не пишется** — `LogMailer` заменяется до выкатки (G2).
- Сторонних аналитических SDK нет; события — своя таблица `product_events`.

## Защита данных

- TLS на всех соединениях, шифрование диска БД и бэкапов средствами хостинга в РФ.
- Для plan-web заголовок `Content-Security-Policy` без внешних скриптов: токен и последний отчёт лежат в `localStorage`.
- Перед стартом нужны утверждённый `CONSENT_VERSION` (не `-proto`) и настоящий почтовый провайдер: `LogMailer` в production письма не отправляет и код не пишет.

## Smoke

| Проверка | Ожидание |
|----------|----------|
| `GET api.plan/api/health` | 200, `env=production`, `database=connected` |
| Вход по коду на тестовый ящик команды | письмо пришло, `verify` → токен, `GET /api/me` 200 |
| Токен игры в `Authorization` к plan-api | 401 |
| Быстрый старт → черновой отчёт → `complete` | отчёт с 3 шагами, повтор с тем же `Idempotency-Key` — тот же отчёт |
| `DELETE /api/me` → `purge` | вход 403 `account_deleted`, после purge строк пользователя нет |
| Игра: `GET /api/health`, вход, «Завершить ход» | без изменений |

## Откат

Предыдущий образ plan-api + миграции только аддитивные (новые таблицы и колонки), поэтому откат кода не требует отката схемы. Разрушающая миграция — отдельный план с бэкапом перед ней.
