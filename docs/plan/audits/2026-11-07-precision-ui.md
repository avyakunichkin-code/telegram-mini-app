# P3-11 · точность и подсказки · 2026-11-07

Основание: выбор владельцем P3-11 и утверждение **«Да, делаем А»** после показа [precision-round](../../../design-lab/plan-checkup/precision-round/APPROVED.md). Это локальный перенос в мастер, без публикации и реальных анкет.

## Реализация

- `apps/plan-web/src/precision.js` — чистый анализ предварительной точности, широкого диапазона и приоритета уточнения.
- `screens/precision/PrecisionInput.jsx`, `PrecisionStatus.jsx`, `precision.css` — утверждённая подача A; `Refine.jsx` использует их во всём мастере, сохраняя поля и порядок вопроса со входа.
- Бейдж в каждом разделе — общая оценка по текущему вводу, явно отделённая от сохранённого отчёта. Разделы без вклада в существующую шкалу не получают ложный статус «уточнено».
- Широкий диапазон строго >3; нулевая нижняя граница с положительной верхней обозначается без деления на ноль. Это предупреждение: сохранение не блокируется. Пустые, отрицательные и перевёрнутые границы блокируют отправку; они не нормализуются в точный ноль. Пустые обязательные scalar-поля и дробные целые также требуют исправления.
- Приоритет: наибольшая сумма неточных весов раздела. Стабильный tie-break — доходы, расходы, накопления, долги. Для кредита вес — месячный платёж, для диапазона — верхняя граница. Пороги и правила анализа не менялись.
- Оценённый кредит не становится уточнённым после смены имени/платежа: пользователь должен отредактировать остаток и ставку договора; пока оба поля не введены корректно, estimated сохраняется. Не требуется вводить новый серверный контракт.
- Строки имеют стабильные UI-ключи; удаление строки не переносит mode другого поля. Busy блокирует поля, переходы, удаление/добавление. Сохранение защищено от повторного запроса и позднего ответа после смены сессии/экрана.
- `App` сохраняет форму Refine при потере/возвращении сети, не заменяя несохранённые строки офлайн-отчётом или перезагруженным черновиком. Офлайн-отчёт на экране Report продолжает работать как раньше. Форма существует только в памяти: перезагрузка браузера не обещает сохранения несохранённых полей.

Это не новая статистическая достоверность прогноза. API и финансовые формулы не менялись. Быстрый старт и вход сохраняют существующую композицию; новый компонент применяется в мастере уточнения.

## Сверка и проверки

`scripts/precision-fixtures.py` генерирует 47 вымышленных кейсов вызовом существующего `adapter.precision`; JSON-результаты — `test/fixtures/precision.json`. FE unit сверяет долю с допуском 1e-12 и классификацию; для нулевого набора UI использует честное «Нет сумм», хотя серверный enum остаётся draft. Сырые анкеты и окружение не читаются.

Дополнительные unit: выбор раздела по весу вместо отношения границ, стабильный tie-break, 1.1/50%/85%, нули, >3, пустые/отрицательные/перевёрнутые значения, условия снятия estimated.

Браузерный критичный путь — `e2e/precision.spec.js`: сохранение широкого диапазона; ошибка с сохранением ввода; offline/online без потери строки; бейдж в остальных разделах; удаление первой строки с сохранением диапазона второй; запись estimated через действующий API. Самопроверка, автоматические тесты и независимое ревью не заменяют исходное человеческое утверждение A.

Ограничения: не полный редизайн анкеты; глобальная оценка не измеряет полноту всех разделов. Экранный диктор и реальное устройство не проверены. Автоматическое повышение точности не обещает улучшение конечного финансового результата.
