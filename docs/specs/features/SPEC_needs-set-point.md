# Spec: Потребности — износ, уровень жизни и нелинейная цена балла

Расширяет [SPEC_game-character-needs](SPEC_game-character-needs.md). Заменяет линейный decay из [ADR-005](../../decisions/ADR-005-character-needs-state-and-defeat.md) §3 моделью «износ + уровень жизни» ([ADR-015](../../decisions/ADR-015-needs-set-point-model.md), accepted 2026-10-21). Правило поражения (ноль 3 периода подряд) сохраняется.

## Assumptions

1. **Потребности — двигатель игры** (PO, 2026-10-15). Они падают всегда; без событий игра свелась бы к «Зарплата → Завершить ход». Поражение по потребностям — второй путь к проигрышу и обязано оставаться достижимым для пассивного игрока.
2. Уровень жизни L **не останавливает** падение, а смягчает его: точка, к которой тянется потребность, сдвинута ниже L на постоянный износ рутиной. Деньги отсрочивают поражение, но не отменяют его.
3. Форма кривой цены — **α = 0.30**. Масштабы K, r, износ — стартовые, финальные даёт `/balance-playtest`.
4. L считается из **уже существующих** данных: статьи расходов, активы, просрочки. Новых таблиц нет.
5. Включение — флагом шаблона `needs.model`, по одному шаблону; старая модель `linear` живёт до перевода всех четырёх.
→ Поправьте до реализации.

## Objective

**Why:** сейчас выгода события не связана с его ценой (₽ за балл различаются в 250 раз), а ежемесячный расход не влияет на самочувствие — подписка проигрывает чашке кофе. При этом давление потребностей должно сохраниться: именно оно заставляет участвовать в событиях.

**Who:** игрок (связь «как живу → как быстро устаю»), автор событий (формула вместо догадки), баланс (несколько ручек вместо 174 ручных чисел).

**Success criteria:**

- [ ] Пассивный игрок (только зарплата и «Завершить ход», бюджет шаблона) проигрывает по потребностям за `passive_periods_to_zero` ± 2 периода (старт 16).
- [ ] Аскеза (урезание досуга/связи) и просрочка по долгу **ускоряют** поражение пассивного игрока.
- [ ] Пассивный игрок с любыми регулярными расходами и активами всё равно рано или поздно проигрывает (инвариант п. 3.5).
- [ ] Активный игрок (2 события за период по ~4% зарплаты + «Порадовать себя») держит потребности устойчиво, без поражения 40 периодов; целевой уровень — выше порога distressed (30), калибруется.
- [ ] Регулярный расход и актив повышают уровень, к которому тянется потребность; к ним действует привыкание.
- [ ] Линтер каталога: плюсы выборов `purpose: pleasure` лежат в коридоре кривой ±50%; знаки осей соответствуют `effect_tags`; 0 нарушений в mvp11.
- [ ] Шаблоны с `needs.model: linear` ведут себя как до изменения.

## Модель

### 1. Цена балла (кривая)

```text
x = C / S                         C — ₽, S — monthly_salary персоны
needs_points(C, S) = K_imp · x^α  α = 0.30, K_imp = 40 (калибровка NV-406, 2026-10-21)
```

Используется в авторинге и линтере (шаги 1, 2, 5) и в рантайме для активов (п. 3.3).

| Студент, S = 62 500 | Цена | Баллы | ₽ за балл |
|---|---:|---:|---:|
| конфета | 10 | 2,9 | 3 |
| кофе | 300 | 8,1 | 37 |
| 4% зарплаты | 2 500 | 15,2 | 164 |
| ужин в баре | 5 000 | 18,7 (потолок 15 на ось) | 267 |
| авто | 1 200 000 | 97 (потолок 25 на ось в уровне жизни) | ~12 000 |

K_imp = 40 и потолок 15 на ось подобраны прогоном 4 персон при 2 событиях за период: K 25 / потолок 10 не давали активному игроку подняться выше ~24 (см. [план](../../plans/PLAN_needs-set-point.md#статус-шага-5-2026-10-21)). Форма кривой (α = 0.3) не менялась.

### 2. Закрытие периода

Заменяет `apply_decay` при `needs.model = "set_point"`:

```text
N[ax] ← clamp( N[ax] + r · (L[ax] − N[ax]) − w[ax], 0, 100 )
r = adaptation_rate = 0.05
```

- **`r · (L − N)`** — притяжение к уровню жизни. Делает состояние активного игрока устойчивым: при высоких N притяжение тянет вниз, при низких — вверх.
- **`w`** — износ рутиной, действует всегда. Без событий потребность стремится к `L − w / r`; износ подобран так, что это значение **ниже нуля**.

Износ по оси выводится из параметра шаблона `passive_periods_to_zero` (T, старт 16): пассивный игрок с бюджетом шаблона доходит от `initial` до нуля за T периодов.

```text
q   = (1 − r)^T
N*  = − q · initial / (1 − q)        ← куда тянется пассивный (ниже нуля)
w   = r · (base − N*)
```

Пример, Студент, comfort: initial 72, base 58, T 20 → w ≈ 4,9 за период.

### 3. Уровень жизни L

```text
L[ax] = clamp( base[ax] + min(bonus_cap[ax], budget⁺[ax] + assets[ax]) + budget⁻[ax] + stress[ax], 0, 90 )
```

#### 3.1. Бюджет — относительно нормы персоны

Для категории расходов c с нормой шаблона `b_c > 0` и текущей суммой активных статей `a_c`:

```text
d_c = K_L · ((a_c / b_c)^α − 1)          K_L = 40
```

- Если `d_c > 0` (тратишь больше нормы) — вклад умножается на привыкание `h(age)` (п. 3.4), age — периоды с момента роста статьи.
- Если `d_c < 0` (урезал) — без привыкания: потеря ощущается полностью, пока статья урезана.
- Категория без нормы (`b_c = 0`): `d_c = needs_points(a_c, S) · 0.4`.

Норма `b_c` — `expense_budget_for_template` ([expense_defaults.py](../../../backend/app/finance/expense_defaults.py)). Статьи событий (`expense_line`) идут в свою категорию. Legacy `monthly_lifestyle_delta`: рост — в `other`, урезание — равномерно по категориям пропорционально норме. Возраст роста категории — `created_period_index` последней статьи из событий.

| Категория | comfort | status | social | health |
|---|---:|---:|---:|---:|
| food | 0,4 | | | 0,6 |
| transport | 0,8 | 0,2 | | |
| communications | 0,4 | | 0,6 | |
| health | | | | 1,0 |
| clothing | 0,4 | 0,6 | | |
| leisure | 0,2 | | 0,6 | 0,2 |
| other | 0,5 | | 0,5 | |

Переопределяется `needs.set_point.category_axes`.

#### 3.2. Стрессоры (пока условие активно, без привыкания)

| Условие | comfort | status | health |
|---|---:|---:|---:|
| есть просрочка (`total_overdue_amount > 0`) | −10 | −5 | −5 |
| `cash < 0` на закрытии | −5 | | |

#### 3.3. Активы

```text
assets[ax] = Σ_asset min(25, share[kind][ax] · needs_points(value_equiv, S)) · h(age)
```

| kind | value_equiv | comfort | status |
|---|---|---:|---:|
| `car` | `asset_value` | 0,6 | 0,4 |
| `home` (owned) | `asset_value` | 0,7 | 0,3 |
| арендованное жильё / `rental_car` | 12 × месячная аренда | 0,8 | 0,2 |
| финансовые (`deposit`, `bond`, …) | — | 0 | 0 |

**Стартовые активы шаблона** (`blueprint.assets`) — норма персоны, как бюджет шаблона: бонус дают только новые покупки, а продажа стартового актива снижает L (источник `asset_lost`, без привыкания). Сопоставление — по `kind` и стоимости.

Покупка актива дополнительно даёт разовый всплеск по кривой (п. 4) — «радость от покупки».

Финансовые и доходные активы (`rental_*`, `land`, `car_taxi`, депозиты) — 0.

#### 3.4. Привыкание

```text
h(age) = h_min + (1 − h_min) · 0.5^(age / h_half)       h_min = 0.4, h_half = 6
```

Новая подписка или машина сначала даёт полный вклад, через 6 периодов — 70%, со временем — 40%. Опора — гедонистическая адаптация: к вещам привыкают быстрее, чем к впечатлениям ([idea](../../vision/ideas/needs-value-curve.md#источники)).

#### 3.5. База, потолок и инвариант давления

- `base[ax] = needs.set_point.base[ax]`, по умолчанию `round(0.8 · initial[ax])`.
- `bonus_cap[ax] = min(bonus_cap_max, 0.8 · (w[ax] / r − base[ax]))`, `bonus_cap_max = 12`: суммарный положительный вклад бюджета и активов на ось. Множитель 0.8 оставляет запас 20% до точки, где падение остановилось бы.
- **Инвариант:** `base[ax] + bonus_cap[ax] < w[ax] / r` для каждой оси. Тогда без событий любая потребность рано или поздно уходит к нулю, сколько бы игрок ни тратил на уровень жизни. Потолок выводится так, что инвариант выполняется автоматически; тест проверяет все сиды.
- Пример (T 20, r 0.05): у всех осей Студента потолок 12; Предприниматель social — 9,8. Чем ниже стартовое значение оси, тем меньше её можно «купить» уровнем жизни.

### 4. Разовые всплески (`needs_delta` событий, treat-self, покупка актива)

```text
gain = raw · max(0.25, (100 − N) / 100)          запас до 100, только для raw > 0
N ← clamp(N + gain, 0, 100)
```

Применяются после шага закрытия (как сейчас — в момент выбора). Минусы — без множителя. Потолки (линтер): `pleasure` ≤ 15 на ось за выбор, treat-self ≤ 25.

### 5. Проверка модели (первая симуляция; K_imp 25, r 0.10, T 16 — заменена калибровкой в [плане](../../plans/PLAN_needs-set-point.md#статус-шага-5-2026-10-21))

Стратегия «активный»: каждый период 2 события по X% зарплаты на две самые низкие потребности (70/30) + «Порадовать себя» раз в 15 периодов (8% зарплаты).

| Стратегия | Студент | Предприниматель |
|---|---|---|
| пассивный | поражение на 18 | поражение на 17 |
| пассивный, урезал досуг и связь на 70% | поражение на 13 | поражение на 9 |
| пассивный + просрочка | поражение на 15 | поражение на 14 |
| активный, 2 × 2% | жив, минимум ≈ 18 | жив, ≈ 22 |
| активный, 2 × 4% | жив, ≈ 21 | жив, ≈ 26 |
| активный, 2 × 7% | жив, ≈ 25 | жив, ≈ 30 |
| активный 2 × 4% + 2 500 ₽ связь + 2 500 ₽ досуг | жив, ≈ 22 | жив, ≈ 26 |
| активный 2 × 4% + авто 1,2 млн | жив, ≈ 24 | жив, ≈ 30 |

Выводы для калибровки:

- Давление работает: бездействие, аскеза и долги ведут к поражению в разные сроки.
- Активный игрок устойчив, но его уровень пока ниже порога distressed (30). Целевой уровень 35–50 — поднять K_imp или снизить износ в `/balance-playtest` (шаг 4, NV-406).
- Вклад уровня жизни в равновесие пока мал (+1–4) из-за привыкания и `bonus_cap` — проверить, достаточно ли он ощутим для игрока.

Симуляция выполнена без `bonus_cap` (п. 3.5): у строк с подпиской и авто значения могут быть на 1–2 балла ниже. Скрипт переносится в `backend/scripts/` и пересчитывается в NV-405.

## Rules & edge cases

- **Ноль для поражения:** при `set_point` шкала считается нулём, если `N < zero_threshold` (1.0).
- **Стартовые значения выше base**: первые периоды потребности падают быстрее — ожидаемо.
- **Норма категории отсутствует** у старого профиля: `ensure_profile_expense_lines` делает backfill; если норма всё равно 0 — абсолютный расчёт (п. 3.1).
- **Истёкшие статьи** выпадают из `a_c` в том же закрытии.
- **Лимит `EVENT_LIFESTYLE_DELTA_ABS_CAP`** (±15 000) сохраняется.
- **Порядок закрытия периода:** списание расходов → истечение статей → расчёт L → шаг «притяжение − износ» → проверка нуля/streak (место `_apply_needs_decay`).
- **Treat-self** — всплеск по п. 4; кулдаун 15 без изменений.
- **Rescue-вес** — без изменений, от текущих N.
- **Инвариант давления** (п. 3.5) — проверка конфига шаблона; тест на все сиды.
- **Модель `linear`** — текущее поведение байт-в-байт.

## Boundaries

- **Always:** флаг `needs.model` на шаблон; `linear` не трогать; pytest + balance-playtest на каждый шаг, меняющий числа; `economy-reviewer` после шагов 3–5; инвариант давления в тестах.
- **Ask first:** перевод шаблона на `set_point` в проде; миграция для периода покупки актива; новые поля в UI.
- **Never:** конфиг, при котором пассивный игрок не проигрывает; менять правило «3 периода нуля» без нового ADR; хардкодить K в событиях.
