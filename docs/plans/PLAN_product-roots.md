# Перенос в самостоятельные корни продуктов

Это технический план утверждённой миграции, не новый продуктовый backlog.

## Срезы и критерии

1. Карта, ADR и инвентарь исходного рабочего дерева. Архитектура утверждена;
   начальные изменения пользователя сохраняются, env/credentials не читаются.
2. Продуктовые корни и документация. Назначить владельца каждого каталога,
   перенести документы, пересчитать относительные ссылки, добавить точки входа.
3. Код и shared. Переместить без изменения поведения, исправить относительные
   файловые пути, requirements, Vite, Playwright, CI, asset manifests и скрипты.
4. Дизайн и lab. Перенести источники и утверждения; производные обновлять только
   генераторами. Сохранить происхождение исторических артефактов.
5. Лендинги. Развязать GAME-сборку; отдельно мигрировать Git-историю PLAN-лендинга
   и определить единственный источник без публикации сайта.
6. Проверки: Codex checker/tests, conventions, backend pytest, оба frontend
   unit/build, GAME guardrails, общие контракты, критичные E2E, сборки лендингов.
   Результаты записывать с exit code. Исходные ошибки отличать от регрессий переноса.

## Ограничения и откат

Много незавершённых продуктовых изменений уже присутствовало перед миграцией.
Не использовать git reset/clean или автоматический staging. Игнорируемые данные,
env и локальные БД не читать. Защищённый снятый контур не редактировать;
совместимость его старых путей явно учитывать при переносе.
Обратный перенос восстанавливает пути; исправления ссылок обращаются отдельно.

и в прежнем layout на расчётных исходниках, совпадающих с исходными хешами.
Порог и финансовые алгоритмы не изменены. Полностью зелёный PLAN pytest не заявлен.
