# Система документации

Продуктовые документы GAME находятся в game/docs/, PLAN — в plan/docs/.
Общие решения — docs/decisions/, общие миграции — docs/plans/,
инженерные процессы — docs/engineering/, шаблоны — docs/templates/.

При конфликте источников поведения:

1. **Поведение в production** — код + тесты.
2. Spec фичи соответствующего продукта.
3. Foundation соответствующего продукта.
4. Vision / ideas — направление, а не детали реализации.
5. Backlog — приоритет, не спецификация.
6. Audits — снимок; не канон до утверждения в spec/ADR/backlog.

Процесс: идея → утверждённая spec → план → реализация → проверка.
Обычная опечатка или понятный баг не требуют четырёх новых документов.
ADR отвечает «почему», spec — «что», plan — «как», ARCHITECTURE — «как устроено».
Approval человека не заменяется отчётом агента или зелёным тестом.
Исторические ADR сохраняют идентификаторы и происхождение, поправки обозначаются явно.
