# ADR-015: Потребности — износ рутиной и уровень жизни

## Context

[ADR-005](ADR-005-character-needs-state-and-defeat.md) §3 задаёт линейный износ: каждая шкала теряет `initial / periods_to_empty_target` за период независимо от того, как живёт персонаж. Последствия (анализ каталога 2026-10-15):

- ежемесячные расходы (подписки, жильё, машина) не влияют на потребности, поэтому всегда проигрывают дешёвым разовым событиям;
- выгода события не связана с ценой: ₽ за балл различаются в 250 раз.

Требование PO (2026-10-15): потребности — двигатель игры. Они обязаны падать всегда, иначе игрок перестаёт участвовать в событиях; поражение по потребностям — второй путь к проигрышу, потому что уйти в минус по деньгам почти невозможно.

## Decision

1. При `blueprint_json.needs.model = "set_point"` закрытие периода: `N ← N + r · (L − N) − w`, `r = 0.10`.
2. `w` — износ рутиной, выводится из `passive_periods_to_zero` шаблона: пассивный игрок с бюджетом шаблона доходит до нуля за заданное число периодов (старт 16).
3. `L` — уровень жизни: база персоны + вклад статей расходов относительно нормы шаблона + активы по кривой цены `K · (C/S)^0.3` + стрессоры (просрочка, отрицательный счёт). Положительный вклад подвержен привыканию и ограничен `bonus_cap`, урезание — без привыкания.
4. **Инвариант давления:** `base + bonus_cap < w / r` на каждой оси — без событий любая потребность рано или поздно обнуляется, сколько бы игрок ни тратил на уровень жизни. Деньги отсрочивают поражение, но не отменяют его.
5. Разовые `needs_delta` — всплески с множителем «запас до 100».
6. Правило поражения ADR-005 §4 сохраняется; «ноль» — `N < 1.0`.
7. Модель `linear` остаётся для непереведённых шаблонов.

## Alternatives considered

1. **Вариант A — линейный износ, подобрать масштаб кривой.** Отклонён: ежемесячный расход по-прежнему не влияет на потребности.
2. **Чистая точка равновесия (`N ← N + r(L − N)` без износа).** Отклонён PO: пассивный игрок стабилизируется на уровне бюджета и не проигрывает — события становятся необязательными.
3. **Чистый износ + регулярная поддержка (без притяжения к L).** Отклонён по симуляции: у активного игрока нет устойчивой точки — потребности либо обнуляются, либо упираются в 100 при малом изменении трат.
4. **Каждая статья расхода с абсолютной кривой.** Отклонён: полное урезание бюджета меняло L на 3–4 балла — аскеза почти бесплатна.
5. **Хранить L в БД.** Отклонён: L выводится из статей, активов и долгов.

## Consequences

- Пассивный игрок проигрывает за ~T периодов (как в ADR-005); аскеза и долги ускоряют поражение; уровень жизни его отсрочивает.
- Активный игрок получает устойчивое состояние, зависящее от трат на события; целевой уровень калибруется `/balance-playtest`.
- Числа `needs_delta` каталога mvp11 перекалибровываются под кривую (план, шаг 5).
- Новые поля overview (`level`, `wear`, `level_sources`, `periods_to_zero_if_idle`) — аддитивный контракт.
