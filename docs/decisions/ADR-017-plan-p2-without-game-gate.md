# ADR-017: Продуктовый каркас Plan (P2) не ждёт Pre-Alpha gate игры

## Status

**Accepted** (2026-11-02). **Изменяет [ADR-016](ADR-016-two-products-shared-fincore.md) п.8 (D4)** в части порядка: остальные пункты ADR-016 действуют без изменений.

## Context

ADR-016 п.8 (D4) закрыл продуктовую разработку Plan (SPL-402+) до Pre-Alpha gate игры: Plan не должен отвлекать от α. Поправка 2026-10-27 разрешила прототип без БД и деплоя. P0 закрыт 2026-10-28: путь чекапа проходит на настоящих расчётах `fincore`, golden и balance diff игры = 0.

Что изменилось:

- прототип показал, что Plan развивается рядом с игрой, не задевая её: за P0 в `backend/` и `frontend-react/` не было ни одной правки;
- следующий шаг Plan (БД, вход, JWT `iss=plan`, CI по путям) — это инфраструктура, а не продуктовые решения на людях. Её откладывание не снижает риск игры, а только сдвигает Plan;
- игра идёт к gate в отдельных сессиях; конфликт за один файл есть только в `fincore`/`platform`, а там правила уже жёсткие (аддитивно, balance diff = 0).

PO 2026-11-02: «P2 сейчас, пересмотреть D4».

## Decision

1. **P2 Plan (SPL-402…405) начинается сейчас**, без ожидания Pre-Alpha gate игры. Предусловие SPL-302 (`packages/platform`) остаётся — он делается первым срезом P2.
2. **Реальные пользователи и их данные — только после юриста по ПДн.** До консультации (согласие, политика, данные членов семьи от третьего лица, правила 8–10 spec) Plan не принимает реальных пользователей, не хранит их персональные и финансовые данные и не деплоится наружу. Разработка и тесты — на синтетических данных, письма с кодом — заглушкой в лог.
3. **Деплой (SPL-406) — отдельным решением владельца.** В P2 готовится только план деплоя; выкатку решает PO после юриста.
4. **Общий код — только аддитивно.** Изменения `packages/fincore` и `packages/platform` не меняют поведение игры: golden-тесты зелёные, `balance_playtest.py` без дрейфа к эталонам (balance diff = 0). Перевод игры на `platform` (SPL-301) — отдельный срез с той же проверкой, не в P2.
5. **Изоляция приложений.** `apps/plan-*` не импортирует `backend/` и `frontend-react/`; игра не импортирует `apps/plan-*` (ADR-016 п.4). Код игры (`backend/app`, `frontend-react/src`) в P2 меняется только в SPL-403 (вынос примитивов MQX в `packages/ui-kit`) и только с зелёными проверками игры (build, guardrails, e2e).
6. **P3 (Plan v1 продукт)** — после P2; план срезов готовим сейчас, код P3 — после закрытия P2.

## Consequences

- ADR-016 п.8: фраза «продуктовый Plan … после Pre-Alpha gate» заменена этим ADR; границы прототипа (п.8, ред. 2026-10-27) сохраняются для всего, что идёт к людям до юриста.
- Обновляются: [`docs/plan/ROADMAP.md`](../plan/ROADMAP.md) (gate P2), [`docs/ROADMAPS.md`](../ROADMAPS.md) (связь Game → Plan), строка D4 в [`PLAN_game-plan-split.md`](../plans/PLAN_game-plan-split.md), gate реализации в [`SPEC_plan-v1.md`](../plan/specs/SPEC_plan-v1.md).
- **Цена:** внимание делится между игрой и Plan до α. Смягчение — п.4–5: Plan не трогает код игры, кроме SPL-403 с полным набором проверок игры.
- **Риск:** каркас с БД и входом соблазняет «просто показать людям». Блокирует п.2–3: без юриста — нет реальных пользователей и нет деплоя.

## Alternatives considered

1. **Оставить D4 как есть (ждать gate)** — отклонено PO: инфраструктура P2 не конкурирует с игрой за код, а ожидание только сдвигает Plan.
2. **Снять и юриста вместе с gate** — отклонено: аккаунт с e-mail и финансовыми данными семьи — это ПДн по 152-ФЗ, ошибка здесь необратима.
3. **Сразу перевести игру на `platform` (SPL-301)** — отложено: правка `backend/app` ради Plan в момент, когда игра идёт к gate. Пакет сначала обкатывается на plan-api.
