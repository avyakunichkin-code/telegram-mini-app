# ADR-018: Раздельные рабочие контексты Game и Plan

## Context

Приложения уже имеют свои сборки и API, но проекты Codex указывают в общий
корень, инструкции и вход в документацию преимущественно игровые, а unit-тест
Plan загружает компонент Game. Это смешивает требования двух продуктов.

## Decision

Сохранить монорепозиторий и shared kernel ADR-016. Выделить frontend cwd
`frontend-react/` и `apps/plan-web/`, отдельные чаты, локальные инструкции API,
frontend и документации. Корневой AGENTS задаёт общие правила и маршрутизацию.

Документация имеет отдельные входы `docs/game/README.md` и `docs/plan/README.md`;
корневой индекс нейтрален. После поправки ниже канон Game размещается внутри
`docs/game/`, Plan — внутри `docs/plan/`; копий spec и второго backlog не создавать.
Общие ADR, процессы и библиотеки имеют отдельного владельца — репозиторий.
Дизайн-навигация фильтруется по продукту, утверждения и адреса раундов сохраняются.

Unit-тесты приложения не загружают другое приложение. Проверка общих UI-адаптеров
живёт в `tests/shared-ui/` с отдельным CI job, затрагивающим обоих потребителей.
Новые экраны и общий UI-kit этим решением не вводятся.

## Consequences

### Поправка 08.11.2026: физическое разделение документации

Основание — последующее поручение владельца в чате: «документацию также стоит
разделить на документацию по GAME и документацию по PLAN». Оно расширяет
первоначальное разделение входных страниц до разделения самих документов.
Ранее выбранное сохранение канонических адресов Game заменено этим решением.

Game-документы переносятся в `docs/game/` с прежними слоями зрелости; Plan
остаётся в `docs/plan/`. ADR, AI-процессы, шаблоны, свод и план общего ядра
остаются общими. Старые Markdown-адреса — короткие ссылки совместимости,
исключённые из обычного поиска. Реестр — `docs/product-doc-relocations.json`.
Существующие локальные изменения сохраняются; контракты и поведение продуктов
не меняются. Бинарные ассеты, JSON/SQL-фикстуры, baseline и генерируемые отчёты
сохраняют адреса инструментов; новые документы ссылаются на них явно.

Цена — обновление входящих ссылок и поддержка переходных адресов. Проверка —
реестр переносов, ссылки Game/Plan, поисковые исключения и Codex/conventions.
Это локальная реорганизация, без настройки проектов клиента и без деплоя.

Два небольших набора локальных инструкций и отдельная проверка контракта.
Контекстное разделение не ограничивает файловые права и не очищает старые чаты.
Фактическую настройку проектов клиента следует проверять отдельно от файлов.
Не требуется переезд Game в apps, публикация пакетов или разделение Git.

## Alternatives considered

Отдельные репозитории — пока лишняя стоимость версионирования общих пакетов.
Только переименовать проекты — cwd и смешанные инструкции сохранятся.
Физический перенос Game-документов первоначально отложен: для разделения входов
он не требовался и увеличивал риск сломанных ссылок. Последующее поручение
владельца расширило scope; перенос выполнен по поправке выше с реестром и проверкой.

## Verification and rollback

Codex checker и behavioral tests, unit/build приложений, shared UI contract,
проверки документационных ссылок и фильтра лаборатории. Изменений экономики нет.
Откат — вернуть маршрутизацию и размещение теста, не меняя продуктовые данные,
исторические утверждения и существующие пользовательские изменения.
