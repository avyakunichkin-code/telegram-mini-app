# Post-playtest: MVP 1.x (Game) и MVP 2.x (Plan)

Итог первой волны плейтестов (PA-W1): продукт расходится на **два режима сохранения** с **общей платформенной базой** и разным игровым/продуктовым ядром.

**Соглашение о версиях (канон с июня 2026):**

| Обозначение | Режим | `save_kind` | Аудитория ближайшей волны |
|-------------|--------|-------------|---------------------------|
| **MVP 1.x** | **Game** — игровой симулятор | `game` | Друзья, коллеги; закрытая альфа |
| **MVP 2.x** | **Plan** — планирование на своих цифрах | `plan` | Те же «свои», кто хочет инструмент, не шаблон |

Связанные документы: [`mvp-1-1-product-direction.md`](mvp-1-1-product-direction.md), [`tvoy-hod-evolution-after-mvp.md`](tvoy-hod-evolution-after-mvp.md) §II, [`SPEC_game-plan.md`](../specs/features/SPEC_game-plan.md), [`expenses-mechanic.md`](expenses-mechanic.md), [`PRODUCT_BACKLOG.md`](../backlog/PRODUCT_BACKLOG.md).

---

## Problem Statement

**Платформа (общая):** Как дать «своим» пользователям **стабильный стенд**, **сквозную аналитику**, **возврат через TG** и **точку сбора сообщества** — один раз, без дублирования для Game и Plan?

**MVP 1.2 (Game):** Как довести Game Mode до уровня, где закрытая альфа даёт **осмысленный фидбек** и удержание в чате — при приоритете ops, а не раздувании контента?

**MVP 2.0 (Plan):** Как запустить Plan как **отдельный продукт** («свои цифры»): квиз входа → вкладка **«Аналитика»** → периодный цикл — не смешивая с игровыми шаблонами и событиями Game?

---

### Лексика: «дашборд» = «Аналитика»

| Термин в брифах | Канон |
|-----------------|--------|
| «Дашборд реальных данных» (Plan) | **Чисто лексическое** название из обсуждения Plan; **не** отдельный экран |
| **Вкладка «Аналитика»** | Единая поверхность в game shell (`AnalyticsPremium` → переписка) |
| Источник цифр | **Game** — симуляция шаблона; **Plan** — введённые пользователем данные. Для продукта **не разные экраны**, а один эпик с ветвлением по `save_kind` |

**Смысл вкладки (оба режима):** показать **текущее финансовое состояние**, **проанализировать** динамику и структуру, в перспективе — **рекомендации** (правила / инсайты, без обещания ML на старте). См. эпик **[AN1](../backlog/PRODUCT_BACKLOG.md#эпик-an1--финансовая-аналитика-игрока)** и [`SPEC_ANALYTICS`](../specs/SPEC_ANALYTICS.md).

**Не путать:** **A0 / PA2** — product analytics в `#/admin` (Watchtower); **E1** — движок расходов/burn (данные для аналитики, не UI вкладки).

## Recommended Direction

### Три слоя, не два «релиза в один день»

```text
┌─────────────────────────────────────────────────────────────┐
│  PLT — Platform (общее для 1.x и 2.x)                       │
│  хостинг · домен · product analytics · TG player · чат · auth │
├──────────────────────────┬──────────────────────────────────┤
│  MVP 1.2 — Game          │  MVP 2.0 — Plan                  │
│  события · баланс · juice│  квиз · **AN1** аналитика        │
│  victory · needs · DL1   │  данных · CRUD расходов          │
└──────────────────────────┴──────────────────────────────────┘
```

**Стратегия:** сначала **PLT P0** (один раз), затем **1.2 Game** для первой когорты; **2.0 Plan** — **spec-first** параллельно (квиз + E1), без блокировки 1.2, но без обещания Plan в тот же спринт, что ops.

## PLT — Platform layer (P0 для обеих веток)

**Цель:** один ops-слой; события аналитики с полем `save_kind` и `channel` (tma / pwa / web).

### In (P0)

1. **Инфра:** платный VPS/облако, свой домен, SSL, health + базовый мониторинг (uptime, API latency).
2. **Product analytics 2.0 (v1):** углубление **текущего стека** — **A0 Watchtower**, серверные срезы (как PA-A* в [`PRE_ALPHA_WAVE1_OPS`](../foundation/PRE_ALPHA_WAVE1_OPS.md)), `player_run_feedback`, funnel/KPI в админке ([`admin-platform-evolution.md`](admin-platform-evolution.md)). Воронка: register → `save_kind` → старт → периоды → исход. **PostHog / Amplitude / self-host — отложены** до роста DAU или второго плейтеста.
3. **TG player bot 2.0:** **5 шаблонов** на первую волну — победа/достижение, «сегодня не закрыл период», re-engage D+7 (+ ещё 2 по согласованию с ops); dedupe; opt-out.
4. **Канал/чат** для закрытого сообщества (ops, не код).
5. **Email + подтверждение:** **P3 / последний приоритет** в PLT; до verify — текущий `/api/register` без блокировки login. **AC1** (merge TG↔email) — после verify, если понадобится.

### Out (PLT v1)

- Digest-рассылки ops
- Полная CMS контента
- White-label / B2B2C

## MVP 1.2 — Game (`save_kind=game`)

**Для кого:** друзья и коллеги, закрытая альфа на Game-шаблонах.

**Успех (4–8 недель после PLT P0):** стабильный ops; качественный фидбек (анкета + цитаты); живой чат (N активных); analytics показывает воронку и застревания.

### In

| Приоритет | Работа |
|-----------|--------|
| **P0** | Всё из **PLT** |
| **P0** | Анкета v2 + процесс агрегации (наследие [`PRE_ALPHA_WAVE1_*`](../foundation/PRE_ALPHA_WAVE1_OPS.md)) |
| **P1** | **EVT1** узкий срез: цепочки + 1–2 global/informational |
| **P1** | **V2-BAL** + balance-playtest; гипотеза in-game флагов «легко / тяжело» (нужен mini-spec) |
| **P2** | Визуальная полировка, juice, набор иконок/иллюстраций |

### Out

- Plan UI и квиз
- Полный каталог 20–25 событий/tier
- M12 экран «Развитие»
- Advisor CTA (решение Pre-Alpha сохраняем)
- WD1 wide / полноэкранный web — **после второго плейтеста** (см. решения ниже)

### Game-only 🟡 (из брифа волны)

- Переезд на платные рельсы → **PLT**
- Расширение событий + сложные цепочки → **P1 EVT1**
- Чистка баланса → **P1 V2-BAL**
- Визуал + акценты → **P2**
- Аналитика 2.0, TG, чат, анкета → **PLT** / P0

## MVP 2.0 — Plan (`save_kind=plan`)

**Для кого:** те же «свои», кто хочет **свои цифры**, не игровой шаблон.

**Успех:** пользователь проходит **квиз** → на **«Аналитике»** видит **своё финансовое состояние** (в Plan — введённые цифры) → закрывает ≥3 периода с осмысленным burn; фидбек «понятно, куда уходит зарплата».

### In

| Приоритет | Работа |
|-----------|--------|
| **P0** | Всё из **PLT** (без email verify — см. P3) |
| **P0** | **Квиз Plan** — старт **сразу после выбора Plan** в UI; контент **с нуля** (опросник готовит финсоветник, не PA-W1); product one-pager → `SPEC_plan-onboarding-quiz` |
| **P0** | **AN1** — вкладка «Аналитика»: полная переписка legacy `AnalyticsPremium`; состояние + анализ; Plan после квиза |
| **P1** | **E1** — слой расходов/burn (питает A1); CRUD статей, `starter_params_json` ([`SPEC_expenses`](../specs/features/SPEC_expenses.md) волна D) |
| **P1** | Активация плитки Plan (снять «Скоро»); маршрут: `NewProfileKindScreen` → **квиз** → вкладка «Аналитика» |
| **P3** | Email verify (**AUTH1**) — последний приоритет общей платформы |

### Якорь в коде (уже есть)

- `save_kind=plan` в модели и API start ([`backend/app/services/game/start.py`](../../backend/app/services/game/start.py))
- `BaseParamsScreen` (`saveKind="plan"`) — черновик мастера; целевой split → `screens/plan/`
- Тесты plan expenses: `test_plan_expenses_contract.py`
- Needs **disabled** в Plan ([`SPEC_game-character-needs`](../specs/features/SPEC_game-character-needs.md))

### Out (2.0 v1)

- События Game (tier, chains) в Plan-партии
- Достижения M12 в Plan ([`SPEC_achievements`](../specs/features/SPEC_achievements.md) — game-only v1)
- Налоги, банкротство, полный expense CRUD с due-датами
- Полная parity Game-экономики (инвестиции, страховки как в симуляторе) — по отдельным эпикам

### Plan-only 🟡 (из брифа волны)

- Квиз начальных экранов → **P2-ONB** (idea → `SPEC_plan-onboarding-quiz`)
- Вкладка «Аналитика» → **AN1** (общий для Game и Plan; E1 — данные расходов)
- Остальные 🟡 → **PLT**, кроме пунктов Game-only в матрице выше

## Key Assumptions to Validate

- [x] **Analytics v1** — углубление Watchtower/SQL, без внешнего SaaS на старте (2026-06-21)
- [x] **Квиз Plan** — с нуля, советник; триггер = тап Plan (2026-06-21)
- [x] **WD1** — полноэкранный wide web **после** 2-го плейтеста; до тех пор вертикаль ~480px (TMA + PWA/web) ([ADR-012](../decisions/ADR-012-primary-channels-pwa-web-over-tma.md))
- [ ] Закрытая когорта готова играть в **Game** без Plan — Plan — подмножество с явным интересом
- [ ] Квиз Plan укладывается в **одну сессию 10–15 мин** до первого экрана «Аналитика» (зависит от опросника советника)
- [x] **«Дашборд реальных данных»** — лексика Plan; **экран = вкладка «Аналитика»**; эпик **AN1** (состояние → анализ → рекомендации); Game/Plan — ветка данных по `save_kind`, не два UI (2026-06-21)
- [ ] Платный стенд снимает pain resume/cold start с free tier
- [ ] TG re-engage D+7 приемлем при 10–30 DAU

## Not Doing (and Why)

| Тема | Почему |
|------|--------|
| Два отдельных деплоя для Game и Plan | Один API, один фронт, `save_kind` |
| Plan в том же спринте, что EVT1 full | Разные домены; E1 не готов без квиз-spec |
| Advisor CTA в альфе | Решение 2026-05-30 |
| Дублировать PLT работы в эпиках M11/EVT1 | Только ссылки на **PLT** |
| PostHog / Amplitude / отдельный analytics SaaS | Сначала Watchtower + SQL; внешний стек — после 2-го плейтеста |
| WD1 wide layout до 2-го плейтеста | Вертикальный формат TMA/PWA достаточен; PWA/web primary, TMA не снимаем |
| Префилл квиза из PA-W1 | Квиз Plan — отдельный опросник советника |
| Email verify в P0 | Последний приоритет PLT |
| Studio `architecture.md` / GDD-пути | Канон: specs + ADR ([`ARCHITECTURE_ASSESSMENT_2026-06.md`](../ARCHITECTURE_ASSESSMENT_2026-06.md)) |

| 6 | TG templates P0 | **5 шаблонов** на первую волну. |
| 7 | Plan «дашборд» vs Аналитика | **Лексика:** «дашборд реальных данных» = разговорное имя Plan. **Продукт:** одна вкладка **«Аналитика»**, эпик **AN1**. Источник цифр (симуляция vs реальные) не меняет миссию: состояние, анализ, в перспективе рекомендации. |

| 9 | AN1 продуктовые якоря | Единые **стандарты** (не сложность Game); прогноз **3/6/12** мес.; победа **не в фокусе**; рекомендации — **авто** rule engine; личное/семья **не** разделяем; AN1 **без** gate E1 — см.
