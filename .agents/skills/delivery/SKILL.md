# delivery

Определи продукт по рабочему каталогу, путям задачи и поручению. Выбери стадию по
[общему маршруту](../../../docs/engineering/CODEX-PROCESSES.md); открой только профиль
выбранного продукта. Если задача из корня затрагивает несколько контуров, назови их.
Idea → spec → plan → implementation по имеющимся согласованиям. Понятный баг:
воспроизведение → минимальная правка → проверка; для опечатки не создавай эпик.
Используй существующие roadmap/spec/plans, сохраняй в плане прогресс, решения,
проверки и незакрытые вопросы для продолжения работы. Новые параллельные реестры
GOALS/PLANS/PROMPTS не требуются. Специализированный UI или экономика GAME →
его локальные навыки; UI PLAN → процесс дизайна PLAN. Согласование среза разрешает
локальные правки в нём, но не деплой, публикацию, commit или смену baseline.
