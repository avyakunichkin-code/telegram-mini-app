# Clarify first (ТВОЙ ХОД)

**Применяется ко всем product-скиллам** до записи в репо, генерации ассетов или verdict **COMPLETE**.

## Принцип

При **любом сомнении** — **STOP**, не угадывать. Лучше один уточняющий вопрос, чем переделка всего среза. Пересмотр самого принципа — [C-X](../../../CONVENTIONS.md); спор с постановкой до работы — [C-Y](../../../CONVENTIONS.md).

| Ситуация | Действие |
|----------|----------|
| Scope неясен (что именно в срезе) | Спросить; кратко перечислить варианты |
| Spec vs код расходятся | Назвать конфликт; спросить приоритет |
| Несколько valid primary skills | Один primary по [matrix](skill-responsibility-matrix.md); при споре — спросить |
| Нужен визуал (иконка, фон, портрет) | [visual-assets-policy.md](visual-assets-policy.md) — **согласовать формат до генерации** |
| «Сделай быстро» без AC | Уточнить критерий готовности или предложить draft-only |
| Пользователь не просил draft | Не сдавать скелет «на потом» |

## Инструменты

1. **`AskUserQuestion`** — выбор из 2+ вариантов (формат ассета, scope, приоритет).
2. **Текст с ASSUMPTIONS** — если вопрос открытый; явно: «исправьте сейчас или продолжу с этими допущениями».

```
ASSUMPTIONS (подтвердите или поправьте):
1. …
2. …
→ Без ответа не перехожу к implement / GenerateImage / Write.
```

## Запрещено

- Молча выбирать интерпретацию при двусмысленном запросе.
- **COMPLETE** / merge-ready verdict, если открыты блокирующие вопросы.
- Подменять согласование фразой «если нужно — скажите» в конце уже готового diff.

## Связь с workflow

Часть фазы **Уточняем** в [delivery-workflow.md](delivery-workflow.md). Не переходить к **Планируем** и **Делаем**, пока блокеры не сняты или не зафиксированы assumptions с явным OK пользователя.

## Draft-only

Если пользователь явно просит **черновик / идею / outline** — уточнение scope достаточно; verdict **DRAFT**, не COMPLETE.
